# ZOOKEEPER-03 actor-aware V2 adapter

The unchanged ZooKeeper 3.8.7 JUnit is `QuorumTest#testSessionMoved`. Its first `DisconnectableZooKeeper` handle creates an ephemeral znode; ten successor handles reuse the same raw session while moving across five peers and issuing writes and syncs. The selected check is `SessionTrackerImpl.setOwner:329`, where a missing or closing session causes `SessionExpiredException` at line 330.

This case copies the established ZOOKEEPER-02 receiver/identity joins into an isolated `zk03` agent. The original test's actual `QuorumBase` binds five `QuorumPeer` receivers, peer SIDs, snapshot directories, and client ports. Each real `ClientCnxn` handle is registered as `handle:0` through `handle:10`, with the same logical `movedSession` tag. Client socket I/O is eligible only when the actual channel destination equals that handle's test-selected peer. Server socket I/O additionally requires the original `ServerCnxn`, its `ZooKeeperServer` receiver, a joined raw session, and peer SID. Epoch file I/O requires the QuorumPeer receiver to own the actual file.

At `setOwner`, the hook inspects the real tracker receiver, its `expirer` server, the current leader peer, the raw moved session, the actual requested owner object, and the session's `missing`, `closing`, or `present-open` state. A guard from another peer/session or an unknown owner is unbound. `TARGET_THROW` requires the selected `SessionExpiredException` and a missing/closing session. The fault plan and target are joined by the same logical session or peer, not by a global call-site ordinal.

Offline `build_adapter.py` verifies the original source commit `9085db92dd679e1e90a63bfe6ae6345ab6cbc4ae`, hashes the original selected source/classes and agent sources, transforms the original bytecode, loads it with `-Xverify:all`, and runs wrong-handle, wrong-destination, wrong-leader/session/owner smoke checks. This phase has not launched the original JUnit cluster. The two `calibrate_healthy.py --run` seeds, their `audit_calibration.py` review, and the independent `campaign.py --run` budget remain pending an assigned slot. Old 80 global-ordinal trials remain historical and do not count toward V2.

`campaign.py` defaults to read-only preparation. Its bound run supports `--slots`, `--worker-count`, and `--max-new-trials`; the target is 80 **effective** trials/max8 faults, conditionally 128/max10 on late novelty. A trial is effective only if its entire ordered plan applies to the selected actor relation and the same leader/moved-session `setOwner` guard executes after the last fault. A source-specific target throw is a candidate for replay/review, not automatically a new bug. The run checkpoint is in `ZK03_RUN_ROOT` (default `/users/ZhenyuLi/zk03-actor-v2-runs`). For an isolated host, `ZK03_SOURCE`, `ZK03_BUILD`, `ZK03_REPORT`, and `ZK03_RUNNER` select the original checkout, build, original classpath receipt, and unchanged JUnit launcher.
