# SOLR-18 independent original-JUnit experiment

The workload is the unmodified Solr 8.11.4 `org.apache.solr.cloud.AliasIntegrationTest#testProperties` (two Jetty nodes and embedded ZooKeeper). The source revision and hashes are in `build.json`. `OriginalJUnit.java` invokes that test with JUnit and adds only start/end events. The uninstrumented original run passed: one test, zero ignored, zero failures, no assumption skip (`healthy-baseline.json`).

The selected check is `ZkStateReader.AliasesManager.setIfNewer` at source line 2347. Its equal-version branch asserts that old and new alias JSON are equal. The original SolrJ bytecode has the `Arrays.equals` call at BCI 109 and the selected assertion `ATHROW` at BCI 148. `PatchSolr18.java` overlays only the original `AliasesManager` and `SolrZkClient` class files, with exact method descriptors and patch-count checks. The first `applyModificationAndExportToZk` with the original `AliasIntegrationTest.testProperties` stack frame selects a manager; the first equal-version JSON check on that manager for ZK version 1, before a second modification and before test finish, is the dynamic target. In the recalibrated healthy trace this is sequence 25, old/new version 1, compare 0, JSON equal true. The healthy test reached 13 equal-version checks and no selected throw. The selected manager's Java identity is per-run; the causal rule identifies it across runs.

Five exploratory fault runs from an earlier recorder are quarantined in `evidence/provisional-before-body-origin`. That recorder treated any TEST-worker modification as a test-body call, even when `tearDown` invoked the same method after an early fault. One run therefore appeared target-retaining solely because cleanup created version 1. The current recorder marks an application `TEST_BODY` only when the exact original `testProperties` stack frame is present. Quarantined runs contribute zero to the current budget or bug count.

`Solr18Probe.java` observes `SolrZkClient.getData`, `setData`, and `exists` calls. Phase 1 observed only `/aliases.json`; its 15 attempts yielded four effective trials and exhausted the target-retaining alias-path feedback frontier. Phase 2 also observes other paths that actually occur before the selected check in the healthy original JUnit. The selected ASM target and the alias-path selector ordinals are unchanged. Its optional fault is a `KeeperException.ConnectionLossException` thrown at the observed call entry. Fault plans use ordered `site@@ordinal` selectors, with normalized thread roles; `FAULT_MATCHED` and `FAULT_APPLIED` are separately recorded. A trial is effective only when every planned fault matches and applies in order and the selected version-1 JSON check occurs after the last fault. Other target throws or JUnit failures are recorded for source review, not automatically classified as bugs.

`CoverageSolr18.java` reads JaCoCo execution data and reports only production classes present in the original SolrJ or Core JAR. `classpath.txt` is the case-local runtime snapshot used for every final-budget JUnit; no other case file is read at build or run time. The build excludes GraphChecker, skeleton, and causynth runtime JARs, as checked in `build.json` and each `run.json`. The source directory name `.graphchecker-sources` is just the location of a clean original Solr checkout; no graph artifacts enter target selection, mutation, or coverage decisions. A nonthrow recording failure was exercised in `recorder-error-path-smoke.log`.

`campaign.py` maintains `evidence/campaign-state.json` and the case `result.json` atomically after each completed trial, and fsyncs `trial-ledger.jsonl`. Its case budget is 80 effective trials, up to eight ordered faults. It reports late production coverage or new pretarget I/O separately; the budget remains 80/max8. Raw trial traces, coverage, and JUnit logs are under `/users/ZhenyuLi/solr18-independent-runs`.

Final result: 124 attempts, 117 ordered fully applied plans, 80 valid selected-check-retaining trials, and a maximum of eight faults. No selected `TARGET_THROW` occurred. The two valid trials with failing JUnit returned the injected `ConnectionLossException` from the test's subsequent raw alias read at line 120; they did not fail in `setIfNewer`. The late new production probes at `ZkStateReader$StateWatcher` lines 1352–1353 are the collection-watch cleanup branch, and the late I/O families read `/collections/collection1meta/state.json` during recovery. The exact source review and JUnit failure categories are in `evidence/source-review.json`; every run is audited in `evidence/final-audit.json`. The remaining feedback queue was preserved in the checkpoint when the 80-effective-trial budget was reached.
