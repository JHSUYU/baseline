# ZOOKEEPER-12 source review of fault outcomes

The exact selected check is `QuorumPeer.loadDataBase()` at source line 1193 (`acceptedEpoch < currentEpoch`). Its selected `IOException` starts at line 1194 and its `ATHROW` instruction is mapped to line 1197. The independent probe observed nine healthy guard hits and no selected throw; all 80 fault runs were reaudited from raw events, and no run executed the selected throw after its final applied fault.

Eighteen strict target-retaining trials had a nonzero JUnit exit: 16 single-fault trials, one two-fault trial (`trial-010`), and one eight-fault trial (`trial-057`). Each log contains the injected epoch read/write `IOException`, `QuorumPeer.loadDataBase`'s `Unable to load database on disk` error, and a `QuorumPeerTestBase.waitForAll` timeout. Source lines 1199–1201 catch the I/O exception and abort that peer's startup. The 1193 guard then ran on one or more other peers, so these trials retain the *source check*, while the peer receiving the epoch fault could not satisfy the original test's all-server startup requirement. None reached the selected 1197 `IOException` arm. These failures are explained by the injected I/O fault and do not establish the selected bug.

`trial-069` is a separate secondary observation. All eight planned faults matched and applied, but the final fault was at `QuorumPeer.readLongFromFile:2186` for peer 0 during the last restart. Raw events show the final application at sequence 301 and no later 1193 guard. The log records the injected read exception, the source line 1199–1201 startup abort, and the JUnit assertion at `CurrentEpochWriteFailureTest:90` that peer 0 became available. Because the final fault directly prevents peer 0 startup and the selected check did not run afterward, this assertion is outside the target-retaining evidence and is not marked as a selected-target bug.
