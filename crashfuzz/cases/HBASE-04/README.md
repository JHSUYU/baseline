Status: **quality complete for the original JUnit and tested I/O families**. The independent graph-free v2 campaign reached its 80-effective-trial/max-8-fault budget after 84 attempts. All 84 fault sequences matched and applied exactly; four placed their final fault after the last target evaluation and were excluded from the effective budget. All original JUnit executions passed; none triggered the selected `TableNotEnabledException`. Production coverage increased from 573 to 613 probes. Trial runtime totaled 4,140.81 s, and full case elapsed time was 4,393.78 s. The last 16 effective trials had no new production probes or stable I/O families, so the conditional 128/max-10 extension did not apply. The GraphChecker woven/skeleton trials below are retained only as `legacy_graph_*` historical evidence. The case-local ByteBuddy/JaCoCo recorder passed an original JUnit healthy run and four representative precise I/O replays without any GraphChecker runtime or skeleton. Eight further independent rounds formed a narrow-coverage pilot; all were exact and retained the target, with no target exception. The v2 healthy seed passed with four target checks, 48 related I/O points, 36 stable I/O families, and 573 production probes.

- Phase 2 uses the GraphChecker runtime JAR and case-local bytecode weaver for six HBase classes (`HBaseAdmin`, `Admin`, `ConnectionImplementation`, `MasterCallable`, `MetaTableAccessor`, and `AbstractRpcClient`). The **fault selection, mutation, and feedback are graph-free**, but the instrumentation and identity construction still depend on GraphChecker and its static skeleton. - Source review: `HBaseAdmin.isTableEnabled` obtains `TableState` with `MetaTableAccessor.getTableState`, which calls `Table.get(Get)` on `hbase:meta`. `HBaseAdmin.executeCallable` invokes `RpcRetryingCaller.callWithRetries`; transient read faults are retried. The target check is a client-side precondition before sending the flush RPC.

The independent selector hashes a stable I/O family and its occurrence ordinal. Meta reads include the target table and flush index; meta writes include the table and state; RPCs include the target table, flush index, stage, and protobuf method. The concrete socket destination is logged but excluded from the hash because the embedded cluster assigns ports dynamically. This JUnit has one mini-cluster destination for each relevant service stage, and the full ordered plan must match before a trial is counted effective.

## Phase 2 extension audit

The runner extended 64/6 to 128/8 because its original feedback counted three trials with new full I/O identities in the last 16 effective trials (`p2_0049`, `p2_0052`, `p2_0053`). A replay of the healthy trace and every prior phase 2 trace shows **zero new stable I/O families** in that window when `hitOrdinal` is removed from `marker + siteId + occurrenceAddress + sourceKey`. The same result holds for the coarser `marker + siteId + sourceKey` key. All three apparent novelty events were later retry ordinals at already observed meta/RPC sites; production method/branch gain was also zero in that window. Therefore, the extra 64 trials are recorded as **additional exploration of deeper fault sequences**, not as an extension justified by a new I/O family. `hitOrdinal` remains part of the exact runtime replay selector.
