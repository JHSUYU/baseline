# ZOOKEEPER-10 source and oracle audit

- Selected check: ZooKeeper 3.8.7 `ObserverMaster.removeProposedPacket(long)` in `ObserverMaster.java:359-375`. After `proposedPkts.peek()` returns a packet whose zxid is no greater than the committed zxid, the bytecode compares the proposed and committed zxids at line 365 (`LCMP; IFEQ`). A mismatch takes the arm that throws `RuntimeException("Unexpected proposal packet on commit ack...")` at line 371. The case-local ASM recorder logs this exact comparison, the two zxids, and this specific `ATHROW`.
- Original workload: Jupiter unique ID selects only invocation `ObserverMasterTest.testInOrderCommits(true)`. Its unmodified test starts two participants and one observer, enables `observerMasterPort`, issues 10,001 asynchronous writes through the observer and another 10,001 through a participant, then waits for both writer latches. The uninstrumented preflight ran one parameterized invocation and passed; its log includes `Starting ObserverMaster`.
- State flow: `Follower.processPacket()` sends `PROPOSAL` to `ObserverMaster.proposalReceived()` and `COMMIT` to `ObserverMaster.proposalCommitted()`. The former queues an `INFORM` packet with the proposal zxid; the latter calls the selected `removeProposedPacket(commitZxid)`. The selected throw means the retained proposal head is older than the commit being processed. A fault-triggered throw would be a candidate requiring comparison with the injected packet/file failure and recovery path, not proof by exception alone.
- The healthy instrumented run passed and observed 20,021 exact selected comparisons, all equal, with no target throw. The recorder intentionally samples high-volume `IO` and normal guard events for queue construction, while keeping every exact matched/applied fault event, every throw arm, and the first target guard after each applied fault. An end-of-run target summary retains the total guard count. JaCoCo records complete probe coverage independently of that sampling; the campaign excludes 154 unchanged JUnit harness probes under `org/apache/zookeeper/test/` and uses 7,956 production probes in its healthy feedback.
- Fault selectors use callsite, peer plus logical stream/file key, and occurrence ordinal. The network hooks cover quorum packet reads/writes; `SyncRequestProcessor` hooks model the transaction log append/commit boundary and identify the server by `getServerId()`. Epoch-file hooks retain peer and basename. `LearnerHandler` events with `sid=0` before decoding `FOLLOWERINFO` are excluded because that key cannot identify a unique connection. The transaction-log key names the logical log, not a distinct absolute file path.
- The test JVM uses only case-local ASM and JaCoCo. GraphChecker and static region skeletons are absent from its classpath. Instrumentation setup attempts that failed before a valid target trace are retained as setup diagnostics and excluded from fault-trial counts.
