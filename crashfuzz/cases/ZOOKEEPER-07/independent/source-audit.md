# ZOOKEEPER-07 source and oracle audit

- Selected site: ZooKeeper 3.8.7 `Learner.registerWithLeader(int)` at `Learner.java:515-525`. During the version-`0x10000` `LEADERINFO` handshake, the method compares the proposed leader epoch with `self.getAcceptedEpoch()`. After handling a greater epoch and equality, the remaining arm creates `IOException("Leaders epoch, ... is less than accepted epoch, ...")` and executes `ATHROW` at line 525. The case-local ASM probe records the second `LCMP; IFNE` decision on line 515 and this exact throw. It also logs the comparison sign so a concurrent change between the two reads can be recognized.
- Original workload: `QuorumRestartTest.testRollingRestart()` uses an embedded three-peer quorum and restarts peers one at a time, waiting for rejoin. `LearnerHandler.run()` sends `LEADERINFO` for a learner protocol version `>= 0x10000`; this test uses `LearnerInfo(..., 0x10000, ...)`.
- Runtime I/O selectors identify a direct quorum packet or epoch-file operation by callsite, peer/epoch-file source key, and occurrence ordinal. Feedback requires every selected checked `IOException` to match and apply in order and the exact selected guard to execute after the last fault. `LearnerHandler.run():472` is excluded because its sid is zero before it reads the initial `FOLLOWERINFO`, so its runtime source key cannot distinguish concurrent handlers. Epoch file keys include peer and basename but not an absolute path.
- JaCoCo supplies independent production coverage. No GraphChecker or precomputed skeleton is on the JUnit classpath. The old three GraphChecker rounds are historical evidence only.
- A target exception after a fault would be a candidate for source review of the leader election and persisted accepted-epoch state. The exception is itself a protocol rejection, so its occurrence alone would not establish a new bug.
