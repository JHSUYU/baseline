# HBASE-32 independent upstream passive calibration

The unchanged `TestRegionReplicaFailover.testLotsOfRegionReplicas` passed in four isolated node0 healthy runs, each with its own data directory and JaCoCo file. Healthy #1 and #2 raw logs, `.exec` files, and exit receipts are in `upstream-passive-healthies.tar.gz` (SHA-256 `346b61959ef9fdeaaeb80fdf39129acef4483562b23137e74578a5c81e4a4d82`). Healthy #3 and #4 raw records are in `upstream-passive-healthies3-4.tar.gz` (SHA-256 `b4c5a15b86d9306d03a285aae6eb5d2f0d10ec6ba9b7721491f2f7a06e46314e`). Their summaries are `upstream-passive-healthy.json` through `upstream-passive-healthy4.json`. Healthy #1 exposed an instrumentation gap; #2 fixed it, #3 validated the RPC actor tag, and #4 validated the per-actor WAL ordinal.

In healthy #3, all nine upstream classes were woven without `PROBE_FAILED`. The original target probe and independent probe both recorded 542 entries; the test table `testLotsOfRegionRepli2` accounts for 540. The actual Master OPENED report callsite executed 600 times: 60 regions × 10 replicas. Its records contain raw secondary and primary region names, replica ID, server name, procedure ID, and attempt ordinal. Exactly 540 of these reports precede a same-region secondary target entry.

The test table's primary flush path executed 540 `CANNOT_FLUSH` WAL marker attempts. All reached and completed `wal.appendMarker` and required `wal.sync`; all were under `RSRpcServices.flushRegion`. A request attribute propagated from `FlushRegionCallable.call` to the primary RPC server and WAL callsite. In healthy #3, 349 of the 540 markers had matching client tag, server tag, raw primary region, secondary replica, target ordinal, and RPC ordinal. A first WAL pilot showed that the marker ordinal shared by concurrent replicas changed across runs, so it did not apply its fault. We changed the ordinal to count the first marker within one raw primary/secondary replica/target actor, independently of RPC retries. Healthy #4 passed the original JUnit with 341 exact-actor markers and no probe failures. Its independent queue seeds 540 Master OPENED, 341 exact-actor WAL append, and 341 exact-actor WAL sync selectors. Asynchronous markers without a provable secondary actor remain excluded.

In healthy #2, `ConnectionImplementation.locateRegionInMeta` made 311 logical `ReversedClientScanner.next` calls on target threads. Actual `ClientService.scan` calls with table2 start rows numbered 1,021: 529 OPEN, 1 NEXT, and 491 CLOSE. All OPEN/NEXT calls ran without the target's thread-local identity. Healthy #3 still has predominantly unlinked OPEN/NEXT calls. The logical next attempts remain evidence, while the unlinked wire RPCs are excluded from injection: table/start-key alone cannot identify the exact secondary replica and target invocation. A CLOSE call is not a metadata read.

Healthy runs had zero table-state `Table.get` attempts or lower `ClientService.get` calls in this target path. A separate one-DNR diagnostic applied one exact client flush RPC exception. It observed the same raw region/replica/target guard, then `META_STATE_GET_ATTEMPT`, an actual `ClientService.get` RPC, and the B7 rethrow. That diagnostic timed out; it is outside both fuzz budgets and is neither a completed JUnit nor a confirmed bug. Its raw trace and JaCoCo file are in `upstream-meta-observe-raw.tar.gz`, with structured evidence in `upstream-meta-observe-summary.json`. Injecting at this post-exception meta Get would bypass the selected B7 rethrow, so it is excluded from the B7-effective queue.

The supplemental Master/WAL campaign has its own checkpoint, trial IDs, nine-class JaCoCo union, and effective denominator. Its zero-trial healthy #3 seed was discarded after the identity correction; no completed fault trial or raw evidence was discarded. A Master report pilot injected exactly once, then the same raw secondary entered the target and the original JUnit passed; it did not evaluate the B7 guard. A revised WAL append pilot injected exactly at `wal.appendMarker`; HRegion caught that IOException and returned `wroteFlushWalMarker=false`, so the same secondary target retried RPC and produced marker 2. The JUnit passed; this single WAL failure did not evaluate B7. The original raw trials and JaCoCo files are in `upstream-pilots-master-wal-unmatched.tar.gz` and `upstream-pilot-wal-v2-raw.tar.gz`, with structured summaries beside this document. These pilots are outside both fuzz budgets. The campaign can mutate such same-actor retries into multi-fault sequences, but counts toward the 80-effective budget only if the same raw actor evaluates the B7 guard after the last fault. The node1 80-effective client flush RPC campaign remains separate. HDFS file operations and asynchronous meta scan OPEN/NEXT are not counted as covered fault sites.
