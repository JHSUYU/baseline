# HBASE-37 target-exception candidate source triage

Verdict: **the exact target exception is reproduced, but these trials do not establish a new HBase bug**. The injected `KeeperException.NoNodeException` is a one-call synthetic loss of the master znode read. HBase deliberately maps that condition to a missing value, throws the selected `IOException`, and catches that exception at the caller to return sentinel info port `0`. The JUnit failure compares that earlier sentinel with a status page fetched later through an independent RegionServer tracker. It is a test snapshot mismatch under this synthetic transient, not proof that HBase served an incorrect master link or lost coordination state.
