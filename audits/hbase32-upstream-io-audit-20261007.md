## ASM correctness and exception model

The commit's inserted callbacks are operand-stack neutral: handler entry loads local 1; `MetaTableAccessor.getTableState(Connection,TableName)` loads local 1 while preserving the pending `Table.get` receiver and `Get`; `ConnectionImplementation.locateRegionInMeta` loads locals 1 and 2 while preserving the scanner receiver; `HRegionServer.reportRegionStateTransition` loads `this` and context while preserving the pending stub/controller/request; and static `WALUtil.writeFlushMarker` loads locals 2, 3, and 4. `ScannerCallable` and WAL callsite callbacks take a zero-argument or string argument without consuming the original invocation operands. The WAL post-call callback also leaves `appendMarker`'s returned `long` on the stack. `ClassWriter.COMPUTE_MAXS` is consistent with these stack-neutral insertions. This is a static verification; healthy calibration must still exclude `PROBE_FAILED`, `VerifyError`, or linkage errors.

The upstream agent in `a40ddf0` is **passive**; `run.sh` still delegates actual fault application to the earlier base agent at `FlushRegionCallable.call:81`. Before promoting upstream probes to fault sites, preserve each API's exception behavior: `Table.get` and scanner `next` expose `IOException`; generated `ClientService.scan` and `RegionServerStatusService.reportRegionStateTransition` throw protobuf `ServiceException` at their stub boundary and HBase translates it; WAL `appendMarker`/`sync` expose `IOException` with action-specific recovery. A bare checked exception thrown at a generated RPC invocation could skip the system's intended translation/retry path. Reject any trial in which the fault removes the target region or the B7 guard/rethrow required by that trial's oracle.

## Healthy calibration required before fuzzing

1. In a fresh no-fault original JUnit run, require exit 0 and JUnit 1/1, all expected `PROBE_WOVEN` classes including `ScannerCallable`, no `PROBE_FAILED`/verifier error, and matching base/upstream `TARGET` counts with exact raw primary, secondary, replica, and ordinal within the run.
2. For any claimed pre-RPC metadata lookup, require `META_SCAN_NEXT_ATTEMPT` and at least one `META_SCAN_RPC` with the same target context before the base `HBASE32 IO` flush-RPC event. A scan-next attempt alone is insufficient. Classify scan open/next/close before using its ordinal in a fault plan.
3. For an OPENED report seed, require the same raw secondary region and replica as the target, the source RS and proc ID, and report attempt before the target; check that the target actually appears after the asynchronous handoff. Do not infer that every report attempt succeeded.
4. For a flush marker seed, require `from_flush_rpc=true`, the same **within-run** raw primary region, action, marker ordinal, `WAL_APPEND_START` and its outcome; if `sync=true`, also require `WAL_SYNC_START` and its outcome. Keep START/ABORT, CANNOT, and COMMIT distinct. The healthy trace may legitimately lack some categories; mark those unobserved rather than filling them by source reachability.
5. `META_STATE_GET` is expected on the handler's exception path rather than the no-fault path. Calibrate its `after_rpc_exception` tag with a bounded already-supported flush-RPC fault, and require exact guard/B7 evidence separately. Do not count a meta-read exception as B7 completion unless the original handler executes its explicit rethrow.

Current verdict: `a40ddf0` corrects the earlier WAL-entry ambiguity and adds meaningful actor/phase fields. Its remaining mandatory identity fix for scan fault mutation is to separate open, next, and close RPCs. All probe-hit and target-preservation claims await runtime calibration; no new bug conclusion follows from this static audit.
