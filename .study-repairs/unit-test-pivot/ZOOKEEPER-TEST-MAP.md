## Readable conditions and expected outcomes

- **05 and 07:** `Follower.java:100-104` and `Learner.java:515-527` reject a leader whose proposed epoch is behind the follower's persisted accepted epoch. A restart workload naturally reaches the epoch handshake; the fatal inequality requires an incompatible epoch sequence. The original test expects all peers to rejoin.
- **06:** `Leader.java:1467-1478` rejects an ACKEPOCH summary more recent than the leader's summary. Rolling restarts provide real ACKEPOCH traffic, but the fatal branch requires the remote follower to be ahead. A generic `testQuorum` startup is also a two-peer source-mapped test, but has less state change.
- **08 and 09:** `LearnerSessionTracker.java:163-193` first tries its local tracker, then applies `!isGlobalSession(sessionId)` after local lookup or ownership fails. A `SessionExpiredException` for an invalid local session is expected. `SessionTrackerCheckTest.testLearnerSessionTracker` directly exercises this logic but creates a tracker without any cluster, so it is a non-cluster positive control only. The selected distributed tests have the needed local-session configuration; runtime branch identity is still required.
- **10:** `ObserverMaster.java:359-375` throws `RuntimeException` if a queued proposal exists but its zxid differs from the committed zxid. The parameterized test has a `true` observer-master branch. `ObserverMasterTestBase.setUp` starts two participants and an observer (`:48-88`); `testInOrderCommits` issues concurrent async writes (`ObserverMasterTest.java:213-270`). A mismatch is a possible protocol/order failure, not demonstrated by ordinary writes.
- **11 and 12:** `QuorumPeer.java:1144-1201` reads persisted zxid and epoch files. In the chosen original test, the `currentEpoch.tmp` recovery path is intentionally exercised; absence of the temporary file would cause the 11 throw. The 12 throw checks a different invariant, `acceptedEpoch < currentEpoch`, and must not be inferred from the 11 recovery test without trace evidence.
- **13:** `ReadOnlyZooKeeperServer.java:122-128` refuses global-session renewal while read-only with `CloseRequestException(RENEW_GLOBAL_SESSION_IN_RO_MODE)`. `ReadOnlyModeTest.java:247-283` expects this behavior and later enables local sessions to verify a local connection can succeed. Reaching this target exception is expected protective behavior, not a new defect by itself.
