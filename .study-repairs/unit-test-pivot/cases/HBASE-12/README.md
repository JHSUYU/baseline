# HBASE-12: disabled-table guard

- Target: HBase 2.6.6 `AssignmentManager.preTransitCheck`, the `isTableDisabled(regionNode.getTable())` branch at `AssignmentManager.java:763`. Its exact exception is `org.apache.hadoop.hbase.DoNotRetryIOException`.
- Original embedded-cluster JUnit: `org.apache.hadoop.hbase.regionserver.TestRegionMove.testDisableAndMove` (two region servers). Healthy execution evaluates B3 twice, at unassign and assign, both false. The final move exits at the preceding B2 check and does **not** evaluate B3, even though the JUnit catches `DoNotRetryIOException` (the B2 `DoNotRetryRegionException` is a subclass).
- `independent/mirror.py` records B3-specific outcomes from HBASE-10 original-JUnit executions without rerunning the same fault sequences. Its strict injection, target-after-fault, exact exception, stable I/O, coverage, and timing fields are separate from HBASE-10/11. These shared runs use a case-local ByteBuddy recorder and JaCoCo on original production classes; they use no GraphChecker code or static skeleton. Shared runtime is nonadditive.
- The B3 target is often lost after response-loss faults on assignment/unassignment, so a separate `independent/unique` campaign uses the **same original JUnit** with an independent ByteBuddy/JaCoCo recorder and prioritizes new request-side fault sequences. Before execution, it checks HBASE-10's completed sequence keys to skip those already run. It also observes HBASE-31's RS start-code guard in the same JVM. Its own checkpoint and target-specific budget begin with a new healthy seed; coverage unions are not mixed across recorder scopes.
- The default budget is 80 effective B3-retaining trials with at most 8 ordered faults, extended to 128/max-10 only if the last 16 effective trials contain genuinely new production coverage or stable I/O families. Every trial records seconds, exact I/O identity, faults actually applied, whether B3 still executes afterward, the exact target exception, and production coverage.
- Stable I/O novelty for this queue uses only I/O **before the last B3 evaluation**. A two-trial setup error that had counted later RPCs as new B3 feedback was corrected in their existing checkpoints with `unique/reconcile_target_prefix.py`; the two JVM executions were retained and did not rerun. The aborted in-flight third trial was restarted from its checkpoint. The initial healthy seed that omitted `RSRpcServices` from the coverage report was archived as a setup pilot; the homogeneous campaign began only after a corrected healthy seed covered all nine production classes.
- `unique/resume_campaign.sh` restarts the tmux campaign from its saved queue and in-flight trial after a process interruption. The `HBASE-12/independent/publish_unique.py` publisher merges the separately attributed shared and unique rows while keeping their distinct JaCoCo coverage scopes explicit.
