# HBASE-16: close confirmation during region-server crash

HBase 2.6.6 `TransitRegionStateProcedure.confirmClosed` checks `regionNode.isInState(State.CLOSING)` at source line 366 and throws `HBaseIOException("Failed to close region")` at line 371. The unchanged original embedded-cluster `TestCloseRegionWhileRSCrash#testRetryBackoff` deliberately kills a region server and waits for close retries. Its counted healthy JUnit passed in 74.89 seconds. The selected `Backoff` region entered `confirmClosed` six times and threw that exact exception five times. JaCoCo covered the throw line. This exception is expected recovery behavior in this original test, so it is the baseline, not a new bug.

The healthy request made four `MasterCallable.call` attempts inside the test's `HBaseAdmin.move` lambda; the first preceded the first target invocation, and later attempts interleaved with close retries. Source at HBase tag `rel/2.6.6` shows this call precedes the `moveRegion` master RPC. A case-local ByteBuddy probe selects only that lambda's encoded `Backoff` region and logs the move request, every selected call attempt, the `confirmClosed` procedure ID and region, and its exact method exit. One healthy run also observed a `CLOSE_RPC` door, but it was absent in another healthy run; the campaign therefore used only the stable `MOVE_MASTER_RPC` door. Exceptions were injected at the call entry, before the master RPC, as `IOException`, `SocketTimeoutException`, `EOFException`, or `ConnectException`.

The independent campaign completed **80 unique ordered trials**, with at most eight faults each: four one-fault, 16 two-fault, 40 four-fault, and 20 eight-fault sequences. All **356/356 requested fault events** matched and applied in exact order. All **80/80 trials** reached `confirmClosed` on the same encoded region after the last fault, and all **80/80 original JUnit runs passed**. Each trial showed five exact `HBaseIOException:Failed to close region` exits, matching the healthy run; no new target exception was observed. The selected production JaCoCo branch union grew from 150 to 154 across nine HBase client/server classes. The new branches appeared at r001 (+3) and r015 (+1). Trials 73–80 added no production method or branch and no new observed I/O family, so the conditional 128-trial/max-ten-fault extension did not trigger. Summed per-run elapsed time was 8,089.34 seconds; fault runs ranged from 69.02 to 120.55 seconds (median 100.67).

The positive target-arm evidence is the exact, source-exclusive exception from `confirmClosed` on the tracked `Backoff` region after the final fault, together with JaCoCo coverage of throw line 371. An attempted direct `RegionStateNode.isInState` advice emitted no `GUARD` marker, so the ledger does not claim a separately observed boolean value. The encoded region identifies the one move request across client and procedure threads. The selected fault door and nine-class production coverage scope limit this observation; they do not establish behavior for every HBase operation or fault.
