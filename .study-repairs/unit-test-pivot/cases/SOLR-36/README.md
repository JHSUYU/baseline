# SOLR-36 original-test campaign

The target is Solr 8.11.4 `DistributedZkUpdateProcessor.doDefensiveChecks` line 986/987. When a child shard leader is already `ACTIVE`, it rejects a `FROMLEADER` add tagged as coming from its parent with a 503 `SolrException`. The mapped original embedded-cluster JUnit is `ShardSplitTest#test`. Two unchanged, passing healthy executions reach the exact guard. The independent ASM recorder observes the exact guard operands and throw, while original release-JAR JaCoCo coverage and observed I/O guide the fault sequence. No GraphChecker skeleton or runtime graph is used.

The first stage injects ZooKeeper native `ConnectionLoss` at exact logical replica/resource/site/ordinal selectors. Trial 58 applied four exact faults, then observed an `ACTIVE` child guard and exact line-987 throw on a parent-forward **add**. Trial 78 applied one collection-scoped fault on a shard2 core, followed by the exact throw on a separate shard1_0 core during parent-forward **delete-by-id**. Both original JUnits passed; the failed requests were accepted after Solr's stale-state retry. In each trial, the parent and target child were separate logical cores hosted by the same physical Jetty. Eight byte-identical replays of trial 58 and four of trial 78 all strictly applied their plans and passed the original JUnit, while none reproduced the exact target throw. The source and test behavior supports temporary collection-state snapshot disagreement with protective 503 responses; the trial 78 fault's influence on the target is unproven. See `independent/campaign/candidate-0058-review.md` and `candidate-0078-review.md` with their frozen trace/replay evidence. These are **not confirmed new bugs**.

The ZooKeeper campaign reached its 128-selected-plan/10-fault cap without repeating trials 1–80. Its state and SHA-backed final audits are frozen in `independent/campaign/milestone-0128/`: 117 trials strictly injected and reached the target afterward under the old logical-source identity rule; the original release-JAR union added 110 production methods, 405 branch outcomes, and 75 semantic I/O families. Trial 77's two original Lucene `DocumentsWriter` probes justified the earlier 80→128 extension. The entire ZooKeeper stage remains actor-unverified legacy exploration. A separate parent-to-child HTTP stage will exercise both original add and delete-by-id calls at `SolrCmdDistributor.submit`, with its own checkpoint, elapsed times, exact sender and child identity, and post-fault target oracle.

The 128-trial budget caps **selected fault plans**, not strict effective trials. A selected plan gets at most two unchanged JUnit attempts. If its full runtime selector never appears, the frozen scheduler records `unmatched`, removes that plan from the queue, and counts its elapsed time in the selected budget; it contributes zero strict injections, post-fault target reaches, and valid coverage. The final report states selected plans, total attempts, strict injections, and same-child effective trials separately. If unmatched plans cause a material effective-count shortfall, a later monotonic budget extension can add new plans without rerunning completed ones.

An independent actor audit found a limitation in this ZooKeeper phase: its injector matched marker/site/logical source/path/ordinal, but did not bind the exact `SolrZkClient` actor or physical Jetty before faulting. The raw trace logs `physicalNode` and `mdcCore`, so the observations and the reviewed 503 candidates remain useful; collection-scoped matches can move between Jettys. At the 104-plan audit snapshot, 38 applied steps were collection-scoped, while 207 replica-scoped steps mapped to their child actor. Its selected, attempted, injection, target, and coverage numbers remain under `legacy_zk_coarse_*`; standard checklist counters start at zero for actor-bound stages. See `../../audits/solr-36-37-actor-identity-2026-10-07.md`. A separate actor-aware ZooKeeper V2 is being prepared.

HTTP calibration ran the unchanged original JUnit three times with the sender-bound ASM agent. All three passed and reached both exact guards. Attempts `healthy-sender-01` and `healthy-sender-03` elected the same raw parent replica `core_node4` and shared 49 complete fault selectors: 31 Add and 18 DeleteById, spanning both child replicas. Attempt `healthy-sender-02` elected `core_node3` and is preserved but excluded from this exact raw-sender selection. `rpc-stage/seed-selection.json` and `seed-audit.json` retain the run identities, trace hashes, original source revision, JUnit results, operands, and physical URLs.

The independent HTTP actor-V2 stage is complete. It ran 172 selected fault plans in 218 unchanged original JUnit attempts, with 140 full injections and **127 strict trials reaching this exact check after the final fault on the same logical and physical child**. Fault depth reached five; the configured ceiling was eight. Forty-five trials reached the exact line-987 throw. The raw operands were `state=active;phase=FROMLEADER`, and the source rejects a parent-forward request when its child is already ACTIVE. All 45 were classified as protective 503 responses, not new coordination bugs; their original JUnits passed. Independent raw actor receipts found zero physical child mismatches. The case's effective trials added 28 production methods and 159 branch outcomes relative to the healthy seeds in three original release JARs, excluding runtime-woven classes. The last eight effective trials added no new production method, branch outcome, or sender-bound HTTP I/O family relative to all earlier effective trials, so the budget stopped at 80 rather than extending to 128.

Seven other faulted JUnit attempts failed `ShardSplitTest.checkDocCountsAndShardStates`: shard1_0 held one more document than the test expected. Six of these retained the selected target and one lost it. They all used parent-to-child HTTP TIMEOUT faults. `SolrCmdDistributor.shouldRetry` and `blockAndDoRetries` show a retry path, but these failures have not been minimized or distinguished from the test's referenced SOLR-5309 issue. They are retained as adjacent candidates, not marked as newly found bugs at line 987.
