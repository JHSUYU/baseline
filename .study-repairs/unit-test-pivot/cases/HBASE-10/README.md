This healthy run therefore does not establish execution of the later B3 disabled-table branch.

The campaign code and `resume_campaign.sh` keep an atomic state plus a JSON checkpoint for every completed trial. An interrupted in-flight trial is rerun with a fresh case-local mini-cluster directory; already completed trials are not rerun. A precise B1 exception after a matched fault is marked as a candidate and requires source review and replay before calling it a new bug.

The first campaign trial injected a precise `SocketTimeoutException` after the `UnassignRegion` RPC response. The client retried `unassign`; the later B2 state check executed and threw the expected `DoNotRetryRegionException`, which made the unchanged JUnit fail before its remaining operations. It is still an effective target trial because the selected B1 check executed after the fault, but it is not a B1 exception or a bug candidate. This run added 24 production probes in retry behavior.

The recorder's fault families are workload RPC requests and responses. Source review of the nearby persistence path found that HBase 2.6.6 writes transition procedures through `RegionProcedureStore` into the master region and its WAL. `MasterRegion.update0` aborts the active master on an ordinary `IOException` while updating this store; that removes the target from the remainder of this single-master original JUnit. Injecting at the outer `MasterRegion.update` entry would bypass that production abort path and misrepresent a file I/O error. We therefore report this campaign's RPC scope explicitly and do not count a synthetic outer-method exception as procedure-file coverage.
