# HBASE-01: dead-server guard during meta lookup

The selected check is in `hbase-client/src/main/java/org/apache/hadoop/hbase/client/ConnectionImplementation.java`: `locateRegionInMeta` reads a region location from `hbase:meta`, obtains its `ServerName`, and at line 1104 calls `isDeadServer(serverName)`. The `true` result throws `RegionServerStoppedException` at line 1105. The original selection lists line 1106, which continues the exception message; the executable throw starts at 1105. `isDeadServer` consults `clusterStatusListener` when it exists, so the check joins meta data with a separate client-side dead-server view.

The original HBase 2.6.6 `TestConnectionImplementation#testMetaLookupThreadPoolCreated` creates a table and calls `relocateRegion` in a two-region-server `MiniHBaseCluster`. `HBase01RecordingTest` inherits that method unchanged and adds only source/request registration around the JUnit lifecycle. The healthy run reaches the exact selected guard once on its safe branch. The oracle is the selected guard's fatal outcome (`#u222=false`), which leads to selected throw site `#u234`; an arbitrary JUnit exception is not accepted as this oracle.

All applied selectors use the healthy run's complete target occurrence address, `hbase01-client#epoch0` source, selected fault site, and hit ordinal 1. The two fault gates are at `#u121` and `#u126` immediately after `ReversedClientScanner.next()`. The second fault in `double03` is reached after the first exception triggers a retry. Every faulted run executes the same target guard after its final injection and finishes the original JUnit with exit 0. The faulted traces expose additional *visits* to the same meta response markers, but no new marker type. Instrumented HBase-client method coverage remains 7; branch-outcome coverage, excluding the two synthetic fault-gate sites, rises from 31 to 47. The second fault kind and two-fault sequence add no branch outcomes beyond `io01`. This is scoped instrumentation coverage, not whole-system basic-block coverage.

The bounded campaign found no selected target exception. It has **not** tested a transition in the dead-server status listener or a region-server crash; the source makes those separate inputs to this guard. The meta response exception trials demonstrate retry and target preservation, but cannot establish that either input to `isDeadServer` became inconsistent. Thus this case is `pending_additional_fault_families`, with no bug claim. The wall time from first static attempt to final trial was about 1,131 seconds, including discarded setup/debugging runs. The three counted fault trials total 93.53 seconds.
