# SOLR-07: `ZkController.register` core availability check

- Original Solr 8.11.4 source commit: `e27f44e`, clean case-local worktree `independent/solr-source`.
- Selected check: `solr/core/src/java/org/apache/solr/cloud/ZkController.java:1325`, `if (core == null)`; the next line throws `SolrException(SERVICE_UNAVAILABLE, "SolrCore is no longer available to register")`.
- Original workload: unchanged `AddReplicaTest.testAddMultipleReplicas`, which starts an embedded SolrCloud test cluster and adds replicas. The uninstrumented JUnit passed in 21.420 seconds. The independently instrumented healthy JUnit passed in 26.198 seconds, hit the exact check 9 times on its nonthrowing branch, and observed 1,179 ZooKeeper I/O calls (253 exact operation-path identities).

This case begins a fresh graph-free campaign. Its previous 30 trials used GraphChecker-derived selectors or frozen woven recorder classes and remain historical evidence under `legacy-graph-result.json`; they are **not** counted here. `independent/probe/weave.py` compiles copies of the clean `ZkController` and six `SolrZkClient` methods, leaving the original source unchanged. The target hook records the guard outcome and context; the I/O hook records exact operation, ZooKeeper path, production caller, and global hit ordinal. Injected faults are `KeeperException.ConnectionLossException` at observed relevant collection-state, leadership, live-node, and Overseer I/O. The campaign uses JaCoCo production coverage and stable caller-operation-resource I/O novelty to mutate and prioritize ordered fault sequences, with a periodic new-I/O-site selection for breadth.

Only trials in which every requested fault matched and applied in order **and** the selected check ran after the final fault contribute coverage feedback or target-exception candidates. The base budget is 80 trials with at most eight ordered faults. If the last eight valid target-retaining trials add production coverage or a stable I/O identity, the same checkpoint extends to 128 trials and ten faults. The original JUnit's own result is logged, but only the exact selected guard's throwing outcome is a target candidate; any candidate requires replay and source review.

The persistent supervisor runs in tmux `solr07-independent`; `solr07-independent-sync` refreshes the 102-check table. Per-trial plan, exact matched/applied events, target timeline, JaCoCo data, JUnit log, elapsed time, and atomic checkpoint are under `independent/evidence/campaign/`. The old GraphChecker evidence is retained separately.

Source review: this guard follows the replica's appearance in cluster state, term registration, leader election and leader lookup. It checks the result of `cc.getCore(desc.getName())`. A ZooKeeper connection failure can stop those earlier stages or cause the JUnit to fail without making this `core == null` branch true. Such failures are recorded separately from the selected guard's exception.
