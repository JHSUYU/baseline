# SOLR-07 actor-aware V2

This adapter runs the unchanged Solr 8.11.4 `AddReplicaTest#testAddMultipleReplicas` against its original three-Jetty embedded cluster. The selected check is `ZkController.register` at source line 1325, `if (core == null)`, whose line 1326 throws `SolrException(SERVICE_UNAVAILABLE, "SolrCore is no longer available to register")`. The original test adds NRT, TLOG, and PULL replicas to `testAddMultipleReplicas/shard1`; all three types can reach the check. The older independent campaign's 128 trials are historical coarse evidence and are not part of the V2 budget.

`Agent` instruments the original `ZkController` and `SolrZkClient` class bytes at JVM load. When `ZkController` installs its actual `zkClient`, `Probe.bind` records the controller and client object identities, raw `nodeName` and `solrHome`, and a stable `JETTY/node1`, `node2`, or `node3` role. The target guard records the exact collection, shard, replica/core-node name, core name, replica type, leader URL, own URL, physical node, and whether the core is present. A guard is eligible only when the controller and client bindings agree, the replica matches its descriptor's core-node name, its own URL matches the bound physical Jetty and exact core, and the leader URL maps to one unambiguous Jetty/core. Unbound or ambiguous operations cannot consume a fault. The target throw event is emitted only for the instrumented source throw, following an eligible null-core guard on the same thread.

The six selected `SolrZkClient` entry methods (`exists` twice, `getChildren` twice, `getData`, `setData`) record object-bound I/O. A fault selector contains logical actor, collection, operation, callsite, exact ZK path, and an ordinal within that actor/site/path. Faults are `KeeperException.ConnectionLossException` at selected collection-scoped ZK calls. Seed generation selects only I/O from the exact `SolrZkClient` used by the chosen target guard in each healthy run. The runtime plan also pins the physical target actor; each fault trial audits the raw client identity of every applied I/O against the later exact target guard. A sibling Jetty's I/O cannot count. The campaign uses JaCoCo production-method/branch feedback and new actor-bound I/O families. It does not construct a causal graph.

Before fuzzing, run `python3 build_v2.py` and `python3 smoke_v2.py`. The build checks original Git revision and writes hashes for the original test source/class, original Solr JARs, and V2 agent. The offline smoke checks original-class ASM hooks and rejects a wrong actor, path, client, or ambiguous Jetty binding. Once an isolated JVM slot is assigned, run `python3 run_v2.py clean-01 --clean` and `python3 run_v2.py clean-02 --clean`, then `python3 calibrate_v2.py`: the latter runs two fresh, fault-free instrumented original JUnits, requires the original test to pass, all three actor bindings, an eligible target with a present core, and at least one common exact target and same-client I/O point. Then run `python3 campaign_v2.py`; state is persisted after each selected trial in `campaign/state.json` and reloaded after interruption. It targets 80 **effective** trials with at most 8 faults per sequence, with a conditional extension to 128/10 if the final eight effective trials still yield code or I/O novelty. `max_selected` is 320 initially, 512 after extension. Queue exhaustion or the selected-trial cap is recorded as a limit, not a completed effective budget.

An effective trial requires every planned fault to match the exact runtime identity and the same chosen target guard to execute after the last fault. The target exception is separately recorded as a candidate observation; source review and replay are needed before calling it a new bug. Faulted runs that remove the target are ineffective. The present injector covers six ZK APIs under this collection only; it does not cover all RPC, file, crash, or reboot behaviors.

Two new instrumented original cluster JUnits on node2 passed, each with all three Jetty roles bound and nine eligible target checks; their common physical actor/core/leader signatures are in [calibration-receipt.json](calibration-receipt.json). The V2 queue completed 16 fault trials, with 6 exact ordered injections, 3 same-actor postfault target checks, and zero selected throws. The independent [raw audit](handoff-v3-audit.json) found no errors and links the immutable [handoff checkpoint](handoff-v3-state-16-selected.json) by SHA-256. A coverage-rich deep branch repeatedly lost the target while 55 fresh one-fault roots remained queued. The V3 scheduler now selects a fresh observed actor-bound root on every other trial and otherwise retains the V2 scoring; it does not alter the probe, workload, oracle, budget, or completed trials. Node2 tmux `solr07_actor_v3_campaign` resumes the same atomic state at `campaign/state.json`. [Guarded calibration](calibrate_node2_guarded.sh), [campaign launcher](campaign_node2_guarded.sh), [V3 selector](campaign_v3.py), and [handoff auditor](audit_v2_checkpoint.py) record the transition. Generated classes, JARs, traces, and checkpoints are local artifacts; the V2 implementation is the source and scripts in this directory.
