# ZOOKEEPER-12: independent original-JUnit replay

The original ZooKeeper 3.8.7 three-peer JUnit method `CurrentEpochWriteFailureTest.testReadCurrentEpochFromAcceptedEpochTmpFile` passed in the healthy run. The selected check is `QuorumPeer.loadDataBase()` at `QuorumPeer.java:1193`, where `acceptedEpoch < currentEpoch` would raise an `IOException` whose `ATHROW` bytecode maps to line 1197. The case-local probe recorded nine healthy guard hits and no selected throw. Source and bytecode were reviewed against commit `9085db92dd679e1e90a63bfe6ae6345ab6cbc4ae`.

The campaign ran 80 new trials with at most eight ordered I/O faults. It chose direct TCP read/write, epoch `FileReader`, and atomic epoch-write sites from healthy and faulted runtime traces. A strict trial required every requested site and ordinal to match and apply in order; a target-retaining trial also required the same source guard after the last fault. Of 80 trials, 55 were strict and 45 retained the target. No trial executed the selected 1197 `IOException` after the last fault; no new selected-target bug was confirmed.

Thirty-one JUnit runs failed: 30 timed out while waiting for all servers, and one (`trial-069`) failed its final peer-0 availability assertion. Eighteen of the timeout runs retained the source check on another peer; the injected epoch-file I/O error had aborted the affected peer's startup. In `trial-069`, all eight faults applied, but the final epoch read fault prevented peer 0 from reaching the selected check. [Source review](evidence/independent/source-review.md) ties these failures to the exact I/O faults, peer context, test frame, and selected check. They are not marked as the selected bug.

Target-retaining runs gained 43 source-reviewed production line IDs across connection, atomic-file cleanup, and epoch-file error handling. No new target-before I/O site family appeared. Trials 73–80 added no new production method/line or stable I/O family, so the 80/max8 budget closed without a 128/max10 extension. Total healthy plus fault JVM time was 2,226.814 seconds.

The recorder was compiled solely from [case-local ASM and probe sources](evidence/independent/agent/src/independent/CoverageAgent.java) and used a [plain original-JUnit launcher](evidence/independent/runner/src/independent/OriginalJUnitRunner.java). All 80 JVM classpaths and agent/runner hashes were checked; selected production and test classes are byte-identical to the clean ZooKeeper build. Neither selection nor execution read GraphChecker or static skeleton artifacts. See [provenance](evidence/independent/provenance.json), [raw-event audit](evidence/independent/audit.json), [per-trial CSV](evidence/independent/trial-summary.csv), and [failure review](evidence/independent/failure-review.json). The [raw JUnit runs](evidence/independent/raw-runs.tar.gz) have SHA-256 `b33544f47152239ae2aa43b248a0920e2cc4ff2cdb4d180fc06669b53f8ee8fe`.

The earlier six graph-dependent trials remain in [legacy evidence](legacy-graph-result.json) and are excluded from these counts. No separate positive-control JUnit for the selected fatal arm was run; the throw identity was established from the exact source and bytecode site, and the healthy run confirmed the guard probe.
