## Strict differential gate

The translated three-fault plan preserves the original logical order: (F0) selected replica CoreAdmin `UNLOAD` POST returns an `IOException` response before the network send; (F1) selected command reader `GET_CHILDREN_STAT` for the collection `state.json` throws `ConnectionLossException` at `StateWatcher.refreshAndWatchChildren`; (F2) the same reader's `GET_DATA` for the same path throws `ConnectionLossException` at `fetchCollectionState`, at the frozen relative second hit after F1. Source line numbers differ between revisions; selectors use class and method identity, operation, resource path, actor, and phase-relative ordinal. Raw trace must prove the same concrete reader object at both ZK faults and selected guard, ordered full application, and a selected target check after F2. Unmatched or target-lost attempts do not count.

Each qualifying failure must retain two *pre-cleanup* wait snapshots, the original guard Boolean and exception, a same-client unwatched `state.json` read **after** that Boolean, and the original JUnit outcome. A direct state read is observational and cannot alter the selected Boolean. Compare multiple fresh parent/fix runs because the 8.11.4 candidate is timing-sensitive. A target exception alone is not a new-bug verdict; only a strict fixed-version failure with the same missing-refresh state and authoritative replica absence supports that SOLR-16257 does not fix this path. If the fixed build passes, inspect other refresh sources before attributing the difference to the patch.
