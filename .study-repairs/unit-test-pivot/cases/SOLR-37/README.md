# SOLR-37 source and original-test audit

The target is the second defensive check in Solr 8.11.4 `DistributedZkUpdateProcessor.doDefensiveChecks`, line 994/995: a child receiving a `FROMLEADER` update from its parent rejects the request if its hash range is not a subset of the parent's range. The mapped original embedded-cluster test is `ShardSplitTest#test`. Two unmodified, passing healthy runs reach this exact `isSubsetOf` call; the fault campaign shares the same JUnit execution with SOLR-36 but records a separate exact guard and throw oracle.

The original split workflow supplies a strong normal-path invariant. `SplitShardCmd` lines 823–848 rejects custom child ranges outside the parent and checks their partition; lines 875–883 derives default ranges by partitioning the parent range. It then creates each child slice using that selected range (lines 296–310). On the sending side, `DistributedZkUpdateProcessor.getSubShardLeaders` lines 868–890 only forwards a parent update toward a child when its current collection-state view says the child is `CONSTRUCTION`/`RECOVERY` **and** its range is a subset of the parent. The receive-side check can fail only if the child sees a different range relationship or receives a request from an invalid parent. This source argument describes the original test path; it does not replace runtime fault trials.

The original JUnit does exercise bad custom ranges in `incompleteOrOverlappingCustomRangeTest` (lines 675–718), but expects the split request itself to fail. Those attempts are rejected before a malformed child is created, so their expected exceptions are not target-line 995 observations.

The first independent fault stage injects exact native ZooKeeper `ConnectionLoss` exceptions into observed I/O and uses original-release-JAR JaCoCo feedback. Through trial 58, 6,232 exact range guard evaluations were `subset=true`, including 54 strict same-child post-fault trials; `subset=false` and line-995 exact throw were both zero. The parent-to-child HTTP send is another directly relevant I/O boundary, so a separate case-local HTTP fault stage is prepared. The final status must retain separate counts for these two modalities and cannot infer a bug absence from the ZooKeeper stage alone.
