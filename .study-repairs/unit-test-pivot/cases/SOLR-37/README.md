# SOLR-37 source and original-test audit

The target is the second defensive check in Solr 8.11.4 `DistributedZkUpdateProcessor.doDefensiveChecks`, line 994/995: a child receiving a `FROMLEADER` update from its parent rejects the request if its hash range is not a subset of the parent's range. The mapped original embedded-cluster test is `ShardSplitTest#test`. Two unmodified, passing healthy runs reach this exact `isSubsetOf` call; the fault campaign shares the same JUnit execution with SOLR-36 but records a separate exact guard and throw oracle.

The original split workflow supplies a strong normal-path invariant. `SplitShardCmd` lines 823–848 rejects custom child ranges outside the parent and checks their partition; lines 875–883 derives default ranges by partitioning the parent range. It then creates each child slice using that selected range (lines 296–310). On the sending side, `DistributedZkUpdateProcessor.getSubShardLeaders` lines 868–890 only forwards a parent update toward a child when its current collection-state view says the child is `CONSTRUCTION`/`RECOVERY` **and** its range is a subset of the parent. The receive-side check can fail only if the child sees a different range relationship or receives a request from an invalid parent. This source argument describes the original test path; it does not replace runtime fault trials.

The original JUnit does exercise bad custom ranges in `incompleteOrOverlappingCustomRangeTest` (lines 675–718), but expects the split request itself to fail. Those attempts are rejected before a malformed child is created, so their expected exceptions are not target-line 995 observations.

The first independent fault stage injected native ZooKeeper `ConnectionLoss` exceptions into observed I/O and used original-release-JAR JaCoCo feedback. It completed 128 selected plans, including the original 80 without rerunning them; 117 strictly injected and reached this guard afterward under the old logical-source identity rule, while `subset=false` and line-995 exact throw remained zero. The SHA-backed checkpoint and audits are frozen in the shared SOLR-36 `independent/campaign/milestone-0128/`. Trial 77 added two exact original Lucene `DocumentsWriter` probes, which justified the 80→128 extension. The parent-to-child HTTP send is another directly relevant I/O boundary, so a separate exact sender/child HTTP fault stage is prepared. The final status retains separate counts for these modalities and cannot infer bug absence from the ZooKeeper stage alone.

Here 128 is a selected-plan cap: the frozen runner allows two original JUnit attempts per plan, then records an absent exact selector as `unmatched` without counting it as strict or effective target coverage. It does not requeue that plan in this stage. Selected plans, total attempts, strict injections, and same-child post-fault target trials are reported separately; further budget can be appended monotonically if the effective count is materially short.

The ZooKeeper injector did not bind the exact `SolrZkClient` actor in its selector; `physicalNode` and `mdcCore` were recorded only after matching. An independent 104-plan raw-trace audit found 38 collection-scoped applied steps that may migrate between Jettys, even though 207 replica-scoped steps mapped to their child actor. All 128 ZooKeeper rounds are retained as **coarse legacy exploration**, not actor-aware high-quality trials. Standard checklist counters exclude them, with raw selected/attempt/target/coverage evidence under `legacy_zk_coarse_*`. See `../../audits/solr-36-37-actor-identity-2026-10-07.md`.

The unchanged original JUnit passed three healthy HTTP calibration attempts, with 102, 102, and 98 exact line-994 guards. Attempts `healthy-sender-01` and `healthy-sender-03` used the same raw parent leader replica `core_node4` and shared 49 exact parent→child selectors for Add and DeleteById across both child replicas; attempt `healthy-sender-02` elected parent `core_node3` and remains excluded calibration evidence. The shared SOLR-36 `rpc-stage/seed-selection.json` and `seed-audit.json` preserve their identities and hashes.

The independent HTTP actor-V2 stage completed 172 selected plans in 218 unchanged original JUnit attempts, with 140 full injections and **82 strict trials reaching this exact check after the final fault on the same logical and physical child**. The exact `subset=false` outcome and line-995 throw both remained zero. The raw operands instead showed both child ranges contained by the parent range, consistent with `SplitShardCmd` and `getSubShardLeaders`. Independent raw actor receipts found zero physical child mismatches. The effective trials added 23 production methods and 98 branch outcomes relative to healthy seeds in three original release JARs, excluding runtime-woven classes. The last eight effective trials added no new production method, branch outcome, or sender-bound HTTP I/O family relative to all earlier effective trials; the budget therefore stopped at 80 rather than extending to 128.

Seven faulted JUnit attempts failed a separate shard1_0 document-count assertion by one document; six retained this target and one lost it. All used parent-to-child HTTP TIMEOUT faults. The source has a retry path, but these failures have not been minimized or distinguished from the test's referenced SOLR-5309 issue. They are adjacent candidates, not line-995 exceptions or confirmed new bugs.
