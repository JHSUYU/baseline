# HDFS-31 actor V3 offline overlay

This isolated overlay is for the unchanged Hadoop 3.4.3 `TestDiskError#testDataTransferWhenBytesPerChecksumIsZero` JUnit. It contains no new healthy calibration or fault campaign results. The older 80 attempts are coarse historical evidence and contribute zero to this V3 budget.

`MiniDFSCluster.startDataNodes` defines a startup episode. The DataNode constructor registers its object, configuration-derived data directories, and ordinal slot before starting BP threads. `BPServiceActor.run` binds its actual DataNode and NN address to the running thread. The `Client.getRpcResponse(Call, Connection)` hook reads the actual `Connection.getRemoteAddress()`; it exposes an eligible I/O point only if that address equals the bound actor's NN address. An unknown or mismatched actor is logged as unbound and cannot consume a fault plan.

The selected production check is `DataNode.getBPOSForBlock(ExtendedBlock)` at the `BlockPoolManager.get` result on released source line 1832, with the potential throw at line 1835. `transferBlock`, guard, and throw records use the passed DataNode object, its current raw UUID, block pool ID, and block ID. They do not infer identity from the caller thread. Fault plans use the ordered tab-separated V2 format and per-actor I/O ordinals. No GraphChecker runtime controller or Docker cluster is involved.

`python3 offline_verify.py` builds the overlay from original released JAR classes and uses `java -Xverify:all` to link all five patched classes without starting a cluster. The 2026-10-07 offline build reported exact hook counts: DataNode target/check/transfer 1 each, constructor registration 1, return registration 2; BlockPoolManager add/remove 1 each; BPServiceActor, MiniDFSCluster, and RPC response 1 each.
