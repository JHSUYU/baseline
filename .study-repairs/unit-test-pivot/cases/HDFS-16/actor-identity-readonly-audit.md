# HDFS-16 actor identity read-only audit

The original Hadoop 3.4.3 `TestClientProtocolForPipelineRecovery#testUpdatePipeLineAfterDNReg` creates one NameNode and two DataNodes, then chooses `cluster.getDataNodes().get(0)` as `dn1`. It disables that DataNode's heartbeat, marks its NameNode descriptor dead, manually calls `registerDatanode(dn1.getDNRegistrationForBP(...))`, and performs two pipeline updates on the same file. The selected `BlockInfo.setGenerationStampAndVerifyReplicas` guard was reached three times in the healthy original JUnit, on block 1073741825. The old 80-trial campaign had 40 strict target-retaining outcomes; this audit does not change those historical counts or rerun any JUnit.

The old `Probe.io` at `Client.getRpcResponse` derives an API name from the call stack and increments one global counter per `(marker, API)`. Its fault plan stores only marker, API, global ordinal, and exception. It does not record the `DatanodeRegistration` UUID, concrete `DataNode` object, IPC client ID/call ID, remote endpoint, or block ID of the RPC. The healthy trace records background `registerDatanode` responses #1 and #2 on identically named `BP-... heartbeating to localhost/...` threads; the original test's manual registration is #3 on `main`. Under an injected fault, retries shift the manual call to #4, so global ordinal cannot identify the intended DN. In the 40 strict target-retaining old trials, 22 include a registration fault: six select #1 and sixteen select #2, none select the manual #3. The two startup responders cannot be assigned to DN0 or DN1 from the trace. Twelve target-retaining trials use only `ClientNamenodeProtocolTranslatorPB` response hooks; six also use an edit-log flush. These remain historical because the response hook also lacks IPC request identity, although the target guard itself records block ID, caller, and generation stamps.

A V2 recheck needs to preserve the original test and bind the selected fault to a real actor: register each MiniDFSCluster `DataNode` startup episode and raw UUID; capture `DatanodeRegistration.getDatanodeUuid()` in `BPServiceActor.register` and in the manual translator call; correlate the actual `Client.getRpcResponse` call ID and endpoint; tag the target with its observed block ID and generation-stamp phase. The existing storage V2 bridge in `hdfs-storage-actor-v2-later/src/{PatchHdfsStorage.java,HdfsStorageProbe.java}` supplies startup episode, DataNode object, BP actor, and raw NN endpoint, but does not yet capture registration UUID. The old 80 plans and their coverage remain preserved; a new isolated checkpoint is needed for unresolved actor-aware plans after HDFS-11 completes.
