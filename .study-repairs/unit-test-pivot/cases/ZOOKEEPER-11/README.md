# ZOOKEEPER-11: independent original-JUnit replay

The original ZooKeeper 3.8.7 three-peer JUnit method `CurrentEpochWriteFailureTest.testReadCurrentEpochFromAcceptedEpochTmpFile` passed in the healthy run. The selected check is `QuorumPeer.loadDataBase()` at `QuorumPeer.java:1169`: if `currentEpoch.tmp` exists, it restores the epoch. When the file is absent, the explicit `IOException` beginning at source line 1174 has its `ATHROW` bytecode mapped to line 1175. The case-local probe recorded one healthy guard hit on peer 0 and no selected throw. Source and bytecode were reviewed against commit `9085db92dd679e1e90a63bfe6ae6345ab6cbc4ae`.

The campaign ran 80 new fault trials, with at most eight ordered faults per trial. It chose direct TCP read/write, epoch `FileReader`, and atomic epoch-write I/O sites from the healthy and faulted runtime traces. A strict trial required every requested site and ordinal to match and apply in order; a target-retaining trial also required the same source guard after the last fault. Of 80 trials, 44 were strict and 25 retained the target. All 25 target-retaining original JUnit runs passed, and none executed the selected `IOException`. Nineteen other runs failed in `QuorumPeerTestBase.waitForAll` after a fault prevented cluster startup; none retained the target. No new bug was confirmed.

Production line coverage gained 11 IDs across target-retaining trials, all source-reviewed as client disconnection or server read/close handling in `ClientCnxn$SendThread.run`, `NIOServerCnxn.doIO`, and `NIOServerCnxn.handleFailedRead`. No new target-before I/O site family appeared. Trials 73–80 added no new production method/line or stable I/O family, so the 80/max8 budget closed without a 128/max10 extension. Total healthy plus fault JVM time was 1,901.584 seconds.
