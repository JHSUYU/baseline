# SOLR-31 source and trial review

- **Original test:** Solr 8.11.4 `ForceLeaderTest.testReplicasInLowerTerms`. It creates three replicas of one shard, lowers follower terms and partitions/stops the old leader, waits until zero replicas are `ACTIVE`, asserts that the shard has no leader, calls `FORCELEADER`, then checks that a new active leader can index and serve documents.
- **Exact check:** `CollectionsHandler.forceLeaderElection` reads the target collection and shard from `ClusterState`, creates `ZkShardTerms`, and rejects the request if `slice.getLeader()` is nonnull and that replica's state is `ACTIVE`. The exact target is the new `SolrException("The shard already has an active leader. Force leader is not applicable...")` at source line 1478. Other ZooKeeper or JUnit exceptions are separate outcomes. A leader elected between the test's pre-request `assertNull` and this server-side check would make this rejection protective; such a candidate would require replay and state review.
- **Healthy reach and calibration:** Two unchanged original JUnit runs pass and each hit this exact guard once with `leader=null`. A full-selector `ZkShardTerms.registerWatcher` ZooKeeper `exists` fault is applied once in the calibration; the same request retries, the original JUnit passes, and the exact guard executes afterward.
- **Campaign:** 80 selected fault sequences, up to eight ordered faults, plus the one separately counted calibration. In the campaign, 79 sequences apply all requested faults at their exact I/O identities, and 78 still reach the target afterward. All 80 original JUnit invocations pass; zero exact target exceptions occur. The longest selected sequence contains six faults. Each trial's elapsed time, selector sequence, fault match, target event and coverage feedback is preserved in the node2 checkpoint.
- **Production coverage:** Union analysis against the original Solr/Lucene release JARs, excluding the runtime-woven `CollectionsHandler` and `SolrZkClient` classes, finds 27 new production methods and 94 new branch outcomes across the 78 strict target-preserving trials. Growth is near saturation: trials 61–80 add one method/four branch outcomes, and trials 71–80 add zero methods/one branch outcome. Semantic ZooKeeper I/O families add zero over the 66-family healthy set; raw sequential znode suffixes are normalized only for this feedback count, never for injection identity.
- **Conclusion:** No exact SOLR-31 exception or new bug was observed in this bounded original-test, ZooKeeper-I/O fault model. This is a complete check for that observed scope. Other fault modalities and original tests that exercise different leader-election interleavings remain outside this result.
