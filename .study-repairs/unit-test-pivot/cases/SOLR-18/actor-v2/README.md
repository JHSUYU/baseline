# SOLR-18 actor-aware continuation

This continuation runs the unchanged Solr 8.11.4 `AliasIntegrationTest#testProperties` embedded-cluster JUnit with assertions enabled. The 80 effective trials in `../independent/` are retained as `legacy_coarse_actor` evidence and never counted here. `calibration.json` records one clean original JUnit pass, two healthy actor-overlay passes, and the unchanged JUnit class SHA-256.

The selected check is the first version-1 equality guard in `ZkStateReader.AliasesManager.setIfNewer` after the test body first calls `applyModificationAndExportToZk` on that manager, before its next modification. `Solr18Probe` records each observed `SolrZkClient.getData`, `setData`, or `exists` call with its live client object identity. `actor_audit.py` resolves the selected manager's enclosing `ZkStateReader` client; an unresolved binding is excluded. An effective trial requires the original test body to start, every planned `ConnectionLossException` fault to match and apply in exact order on that same client, and the selected guard to run after the final fault. Other managers, wrong clients, and runs that lose the selected guard are excluded. The initial healthy traces supply 17 same-client pretarget selectors, including five suite-phase operations that still require the original test body and selected guard to execute after injection.

`campaign.py` is a checkpointed, graph-free coverage and observed-I/O fuzzer. It inserts candidate faults before, between, or after earlier faults in the order actually observed in a valid trace. JaCoCo probes and methods from classes present in the released SolrJ or core jars guide the queue. The default budget is 80 effective trials with at most eight ordered faults. At 80 effective trials, a last-eight production method/probe or stable same-client I/O signal pauses for source relevance review. Only a reviewed relevant signal extends the budget to 128 with at most ten faults. `campaign-state.json` and `trial-ledger.jsonl` hold per-trial elapsed time, eligibility, outcome, coverage, and candidate I/O.

`run_when_space.py` manages the detached `solr18_actor_v2` tmux session. It resumes only above 2.25 GiB node0 free space; `campaign.py` stops between complete trials at 2.2 GiB plus a 16 MiB reserve. Each completed run is mirrored to node2, checked by `rsync -acn` and per-file SHA-256, then local derived coverage text and scratch are pruned. Effective trials and source-review candidates retain local `events.tsv`, `jacoco.exec`, and `console.log`; every run retains local `run.json` and the plan. Completed noncandidate consoles, events, and JaCoCo files are removed locally only after node2 SHA verification. `mirror-receipt.json`, `console-offload.json`, and `noncandidate-raw-offload.json` record per-run hashes and restore paths. `noncandidate-raw-restore-smoke.json` records an actual temporary restore, and `final_audit.py` independently re-reads archived events and validates remote SHA. `scratch-cleanup.json` records remote scratch cleanup. No GraphChecker runtime jar or old Docker campaign is used.

Node2 continuation uses the same absolute classpath and raw root. The node2 clean original JUnit and selected-guard calibration is recorded in `node2-migration-calibration.json`; it does not count toward the fault budget. On node2, the wrapper resumes above 10.25 GiB free with at most four other Java processes, and the campaign stops between trials at 10 GiB free or five other Java processes. New raw `events.tsv`, `jacoco.exec`, `console.log`, and `run.json` stay on node2. Their SHA-256 manifests enter `mirror-receipt.json` as `pending_node0_pull` until node0 pulls a checksum-verified second copy with existing SSH credentials. Node2 does not run the node0 noncandidate offload scripts or delete these raw files. The independent audit distinguishes pending external archives from verified older mirrors.

The bounded pilot stopped at exactly five effective trials in fourteen attempts. All fourteen injected plans had exact fault order; three target-retaining attempts were rejected for wrong-client injection and six lost the selected target. Two effective JUnit failures were the injected `ConnectionLossException` propagating directly from the test's `getData` call at `AliasIntegrationTest.java:120`; the selected JSON equality returned `true`. See `pilot-audit.json`. `final_audit.py` independently rechecks the checkpoint, original JUnit hash, actor/guard eligibility, raw mirror hashes, coverage, and failure classification. A selected assertion failure is a bug candidate only after source review, a healthy control, and exact-plan replay.
