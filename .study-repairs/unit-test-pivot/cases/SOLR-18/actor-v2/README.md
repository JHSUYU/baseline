# SOLR-18 actor-aware continuation

This continuation runs the unchanged Solr 8.11.4 `AliasIntegrationTest#testProperties` embedded-cluster JUnit with assertions enabled. The 80 effective trials in `../independent/` are retained as `legacy_coarse_actor` evidence and never counted here. `calibration.json` records one clean original JUnit pass, two healthy actor-overlay passes, and the unchanged JUnit class SHA-256.

The selected check is the first version-1 equality guard in `ZkStateReader.AliasesManager.setIfNewer` after the test body first calls `applyModificationAndExportToZk` on that manager, before its next modification. `Solr18Probe` records each observed `SolrZkClient.getData`, `setData`, or `exists` call with its live client object identity. `actor_audit.py` resolves the selected manager's enclosing `ZkStateReader` client; an unresolved binding is excluded. An effective trial requires the original test body to start, every planned `ConnectionLossException` fault to match and apply in exact order on that same client, and the selected guard to run after the final fault. Other managers, wrong clients, and runs that lose the selected guard are excluded. The initial healthy traces supply 17 same-client pretarget selectors, including five suite-phase operations that still require the original test body and selected guard to execute after injection.

`campaign.py` is a checkpointed, graph-free coverage and observed-I/O fuzzer. It inserts candidate faults before, between, or after earlier faults in the order actually observed in a valid trace. JaCoCo probes and methods from classes present in the released SolrJ or core jars guide the queue. The default budget is 80 effective trials with at most eight ordered faults. If the last eight effective trials add a relevant production method or probe, or repeatedly expose a new same-client I/O family, the budget becomes 128 with at most ten faults. `campaign-state.json` and `trial-ledger.jsonl` hold per-trial elapsed time, eligibility, outcome, coverage, and candidate I/O.

`run_when_space.py` manages the detached `solr18_actor_v2` tmux session. It resumes only above 2.25 GiB node0 free space; `campaign.py` stops between complete trials at 2.2 GiB plus a 16 MiB reserve. Each completed run is mirrored to node2, checked by `rsync -acn` and per-file SHA-256, then local derived coverage text and scratch are pruned. Original `events.tsv`, `jacoco.exec`, and `run.json` stay on node0 and node2. Candidate `console.log` files also remain local; noncandidate consoles are offloaded only after remote SHA verification. `mirror-receipt.json` records transfers, `console-offload.json` records each removable local console and its node2 restore path, and `scratch-cleanup.json` records remote scratch cleanup. No GraphChecker runtime jar or old Docker campaign is used.

The bounded pilot stopped at exactly five effective trials in fourteen attempts. All fourteen injected plans had exact fault order; three target-retaining attempts were rejected for wrong-client injection and six lost the selected target. Two effective JUnit failures were the injected `ConnectionLossException` propagating directly from the test's `getData` call at `AliasIntegrationTest.java:120`; the selected JSON equality returned `true`. See `pilot-audit.json`. `final_audit.py` independently rechecks the checkpoint, original JUnit hash, actor/guard eligibility, raw mirror hashes, coverage, and failure classification. A selected assertion failure is a bug candidate only after source review, a healthy control, and exact-plan replay.
