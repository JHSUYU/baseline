## Source-review corrections

- HDFS-39/40: `TestFileAppend.testAppendTwice` expects a lease conflict. Its source does not establish the target `COMMITTED` or insufficient-replication branch. The map retains it as a cluster workload candidate with an explicit source mismatch; a runtime trace or a better existing test is required.
- HDFS-49: `TestSnapshot.testSnapshot` creates unique snapshots under normal quota. It exercises snapshot creation but does not show the quota-exceeded branch in source.
- HDFS-50: the original map's normal snapshot test was replaced with `TestSnapshotCommands.testCreateSnapshot`, which explicitly repeats snapshot name `sn0` and expects the target same-name failure.
- HDFS-11/12/14: `TestEncryptedTransfer` is `@RunWith(Parameterized.class)`. Existing isolated adapters choose its default parameter instance for the original method; the class/method in the table remains the original upstream test.

For each case, run a fresh embedded-cluster JUnit trial under GraphChecker. Record exact target region/guard arrival, closure inclusion, matched/injected exception identity, whether the target remains reachable, coverage change, time, and result in the new checklist. A JUnit exception alone is not a new bug claim.
