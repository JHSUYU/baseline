## Comparison with the upstream fix

[Apache commit 97458a5](https://github.com/apache/solr/commit/97458a503bc0e5a4f52c0dc4b211d4d79cd1bccd) states that SOLR-16257 fixes a race between `collectionWatches` and `watchedCollectionStates`. It merges their state into a `StatefulCollectionWatch` under one map. In the [fixed `ZkStateReader.java`](https://github.com/apache/solr/blob/97458a503bc0e5a4f52c0dc4b211d4d79cd1bccd/solr/solrj/src/java/org/apache/solr/common/cloud/ZkStateReader.java#L1709), `registerDocCollectionWatcher` still calls `StateWatcher.refreshAndWatch()` only when its map entry was absent (lines 1709–1723). `StateWatcher.refreshAndWatch` still catches `ConnectionLossException` and logs it without scheduling an immediate retry (lines 1342–1365). Its unified `StatefulCollectionWatch.currentState` can be null while the registration entry exists (lines 232–245, 349–351). The local Solr 8.11.4 source has the same registration-only refresh rule at `ZkStateReader.java:1768–1784` and log-only ConnectionLoss catch at 1374–1392.

The diagnostic's **registration-present/cache-absent before cleanup** is the inverse of the reported SOLR-16257 cache-present/registration-absent race. F1 and F2 interrupt initial refreshes, leaving an existing registration with no observed state. The official patch removes the two-map race but does not directly add a retry for this failure path. This is a source-based inference that SOLR-16257 may not cover the candidate; it is **not** proof that a fixed Solr binary fails. A lazy collection read, a later ZK event, or other version changes could recover the state in some executions. Existing actor-aware replays themselves have both passing and failing outcomes for the same logical plan, so one passing fixed-version trial would be inconclusive.

## Isolated differential needed for novelty

1. Prepare two clean worktrees at the official commit's parent `8827b3c` and fixed commit `97458a5`, with the same unchanged `DeleteReplicaTest` method if it exists in both. Independently rebuild the same actor-aware fault hooks against each revision. Record test class and production class SHA-256s. If the exact original test no longer exists or the hooks cannot preserve their semantics, stop and mark this differential incomparable.
2. In per-run isolated four-node embedded-cluster scratch directories with ephemeral listener ports, run healthy JUnit seeds on both builds to verify the same selected leader/replica/Overseer role sequence. No fixed ports or source-level assertion changes.
3. Replay the frozen role-relative F0→F1→F2 plan. Count only runs with the selected replica HTTP actor and same Overseer reader at both ZK faults and the selected post-F2 guard; retain matched/applied event order, `waitForState` pre-cleanup state, same-client authoritative `state.json`, core directory state, original JUnit result, and JaCoCo. Use multiple independent clean runs because the observed path is timing sensitive. A passing run with unmatched faults is not evidence.
4. Interpret a strict fixed-commit selected failure with registration-present/currentState-null and authoritative replica absent as strong evidence that SOLR-16257 does not repair this path. If the fixed commit consistently passes strict runs, inspect whether it recovered through a new watch, lazy read, or other event before attributing the change to the patch. For a same-8.11.4 comparison, backport the *exact relevant SOLR-16257 source changes* into a separately labeled build only after compiling and auditing its behavior; do not equate a fresh-state workaround with that official fix.

Do not use a generic target exception alone as an oracle: F0 is an intentional CoreAdmin error, and the original synchronous operation may report an error under fault. The candidate's distinctive observation is the original command returning `not_removed` **after** both timeout waits even though the same client's authoritative read finds the selected replica absent and cleanup finished. Until the upstream differential is run, the supported classification is **actor-identified, reproducible correctness candidate; novelty unresolved**.
