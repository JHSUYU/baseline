# ZK03 optional complete-I/O fault family

The first ZK03 actor-aware campaign injects `IOException` before selected socket operations. Its original `QuorumTest#testSessionMoved` workload immediately calls `setData` and `sync` after each handoff, so many pre-I/O faults make that JUnit exit before the next selected `SessionTrackerImpl.setOwner:329` guard. Its checkpoint and raw trials remain separate and immutable.

This independently calibrated extension uses the same original ZooKeeper 3.8.7 revision and the same `QuorumTest#testSessionMoved` JUnit. It adds an I/O family at `NIOServerCnxn.handleWrite` after `packetSent()` has acknowledged a completely written response, and one after a complete client `setData` or `sync` `SocketChannel.write`. A partial write, connection handshake, heartbeat, or unbound session cannot match. The existing ZK03 receiver registry still requires the concrete moved-session client/peer and leader target owner; the target guard must occur after the final applied fault. These hooks follow the separately verified ZK02 complete-I/O experiment, but ZK03 selects its own `setOwner` target.

`build_after_response.py` compiles a **different agent SHA** and checks the transformed original classes, `-Xverify:all`, and wrong-actor/target smoke without running JUnit. `calibrate_healthy.py`, `audit_calibration.py`, `run_trial.py`, `campaign.py`, and `audit_v2.py` use a separate `ZK03_AFTER_RUN_ROOT` and checkpoint. Candidate generation admits only the new complete-write and post-response call sites, and coverage/I/O feedback starts from the union of both fresh healthy seeds. Already completed pre-I/O plans are not replayed or silently pooled with the new agent's feedback. The first pre-I/O stage ended at its 480-attempt cap with 37 effective trials; its independent raw audit passed before this new stage began.

The after-response controller groups I/O feedback across transient channel/connection generations. Its exact injection selector still names the observed generation, actor, callsite, and ordinal in that JUnit run.

Two fresh unchanged embedded-cluster JUnits passed in 3.424 and 3.676 seconds with the original leader peer 5 and ten selected owner/guard receipts each. The first five one-fault plans lost the target because the original test checks `setData` and `sync` before the next handoff. The healthy trace places the third complete server response for each new handle after its `sync` write and before the next `setOwner` guard. `prioritize_tail_responses.py` archived the paused checkpoint and ledger SHA, increased only those nine existing queue scores, and kept every completed trial and pending plan. Eight of the nine source-guided followups were exact, actor/owner bound, and target retaining; one exact fault lost the target. The 14-trial independent raw audit passed, including three new instrumented `NIOServerCnxn.doIO` exception-handling lines in effective trial 6. The 80-effective campaign resumes from that audited checkpoint.
