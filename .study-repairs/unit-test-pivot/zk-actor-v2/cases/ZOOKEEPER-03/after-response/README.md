# ZK03 optional complete-I/O fault family

The first ZK03 actor-aware campaign injects `IOException` before selected socket operations. Its original `QuorumTest#testSessionMoved` workload immediately calls `setData` and `sync` after each handoff, so many pre-I/O faults make that JUnit exit before the next selected `SessionTrackerImpl.setOwner:329` guard. Its checkpoint and raw trials remain separate and immutable.

This **offline-prepared, not yet run** extension uses the same original ZooKeeper 3.8.7 revision and the same `QuorumTest#testSessionMoved` JUnit. It adds an I/O family at `NIOServerCnxn.handleWrite` after `packetSent()` has acknowledged a completely written response, and one after a complete client `setData` or `sync` `SocketChannel.write`. A partial write, connection handshake, heartbeat, or unbound session cannot match. The existing ZK03 receiver registry still requires the concrete moved-session client/peer and leader target owner; the target guard must occur after the final applied fault. These hooks follow the separately verified ZK02 complete-I/O experiment, but ZK03 selects its own `setOwner` target.

`build_after_response.py` compiles a **different agent SHA** and checks the transformed original classes, `-Xverify:all`, and wrong-actor/target smoke without running JUnit. Before any fault trial, this new agent requires two fresh original-cluster healthy seeds and its own isolated checkpoint. Already completed pre-I/O plans are not replayed or silently pooled with the new agent's feedback. Launch only after the first ZK03 campaign reaches a complete trial boundary and its source/agent hashes and result have been audited.
