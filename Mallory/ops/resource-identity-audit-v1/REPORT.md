# Mallory I/O resource identity audit (2026-10-10)

## Finding and severity

**High for future claims that require a particular I/O resource.** The shared `FaultPlan.Point` has no resource field, and `Fault.matches` compares only site, node, epoch, occurrence, hit, and door ordinal (`Mallory/instrumentation/src/main/java/edu/uva/liftlab/mallory/instrumentation/FaultPlan.java:38-59`). `Probe.beforeDoor` increments the ordinal per node, epoch, and site; it records no resource in `DOOR_OBSERVED`, `FAULT_MATCHED`, or `FAULT_APPLIED`, and makes the injection decision before an independent path check (`Probe.java:460-490`). The shared feedback, scheduler, and offline audit likewise omit resource from the candidate replay point and receipt comparison (`Mallory/core/feedback.py:70-77,270-282`; `Mallory/core/scheduler.py:47-59`; `Mallory/core/audit.py:93-107`). A plan for one path can therefore apply at another path if its other fields coincide. An ordinal can also drift across runs, in which case a resource-bound plan should fail closed instead of faulting the wrong path.

**Retrospective evidence limit, not a finding of 87 wrong injections.** At audit start, the checklist marked 87 completed campaigns: HBase 29, HDFS 32, Solr 15, ZooKeeper 11 (`data/mallory/checklist102.json`). HDFS-34 became the 88th completed case while this audit ran; the figures and IDs below refer to the initial 87-case snapshot. Their 87 canonical `config.json`, `result.json`, and `offline-causal-audit.json` files have no `resource` field; 71 available checkpoints contain 252,102 replay-point objects and none has `resource`. The 58 declared causal precision receipts that exist have no resource binding or attestation. Raw trial traces were accessible in the canonical or audit-named campaign directory for 50 of the original cases (HBase 7, HDFS 20, Solr 15, ZooKeeper 8). A read-only scan covered 3,801 event files from these cases; every available plan lacked `point.resource`, and the first `FAULT_APPLIED` plus preceding `DOOR_OBSERVED` events in each trace lacked `resource`. Traces with no fault receipt were scanned up to 150,000 events. **Confirmed completed-case resource mismatches: zero. Resource-specific replay identity independently verified in the listed canonical evidence: zero.** Absence of that evidence does not show that an injection reached the wrong resource or that a causal result is false. The current records cannot establish how many of the 87 encountered more than one distinct resource at a selector.

Healthy `r0000` raw traces were accessible for 49 cases. In 34, at least one site/node/epoch/occurrence tuple emitted multiple `DOOR_OBSERVED` events. This is an ordinal/replay collision *opportunity*, not proof that the calls touched distinct resources: the trace omits the resource value. The cases are HBASE-07, HBASE-23, HBASE-37; HDFS-01, HDFS-15, HDFS-16, HDFS-17, HDFS-21, HDFS-23, HDFS-24, HDFS-27, HDFS-28, HDFS-39, HDFS-40, HDFS-49, HDFS-50; SOLR-01, SOLR-05, SOLR-06, SOLR-07, SOLR-13, SOLR-19, SOLR-21, SOLR-22, SOLR-31, SOLR-36; ZOOKEEPER-01, ZOOKEEPER-05, ZOOKEEPER-06, ZOOKEEPER-07, ZOOKEEPER-10, ZOOKEEPER-11, ZOOKEEPER-12, ZOOKEEPER-13. The other 15 accessible healthy traces did not show a repeated tuple; 38 healthy raw traces were unavailable in those two directories. A repeated tuple alone does not establish a resource-specific causal claim.

A **concrete wrong-resource witness is pending SOLR-15 v1, outside the completed 87**. Its sealed bootstrap checks `FAULT_MATCHED` and `FAULT_APPLIED` at ordinal 42 for `/overseer/queue`, while the intended second parent live-node lookup was at ordinal 47 for `/live_nodes/127.0.0.1:42553_` (`Mallory/ops/seal_solr15_bootstrap_node0_v1.py:116-145`). The compressed raw trace itself contains `FAULT_APPLIED` at sequence 1595 on `/overseer/queue` and the desired live-node `DOOR_OBSERVED` at sequence 1898. That trial is already marked `fault_resource_mismatch`, not a completed positive campaign. SOLR-34 and SOLR-15 agents are preparing case-local pre-injection binding; this audit did not touch their files.

## Isolated fix candidate

`resource-identity.patch` applies cleanly to the current source but has **not** been applied to live shared core. It adds an optional exact `point.resource` predicate evaluated in `Probe.beforeDoor` before injection; the resource-bearing overload records the resource on door and fault events. Shared feedback carries a nonempty observed resource into replay points, the scheduler preserves it, and offline audit compares it. Trial feedback records `resource_identity_status` (`resource_verified`, `resource_mismatch`, or `resource_unverified`) and per-fault planned/matched/applied resource values. Old resource-free plans keep their existing matching behavior and report `resource_unverified`.

The negative Java test stages two paths at the same site: a wrong path at the planned ordinal and the desired path at a later ordinal. The resource-bound plan must apply at neither; it applies only when both exact path and ordinal match. A legacy plan still applies at its ordinal. The Python test verifies replay-point propagation, wrong-path receipt rejection, and `resource_unverified` for a legacy point.

The patch does not extract resources from arbitrary transformed I/O sites. Each adapter or pinned transformer must pass a stable, meaningful resource identity to the new overload at the callsite; dynamic file paths and ZooKeeper ephemeral node names need case-specific binding. Pre-injection equality is a safety gate, not a guarantee that a healthy ordinal remains stable. Promotion should follow the pinned live runs and adapter-specific binding review; retroactive resource claims require new evidence, not a reinterpretation of old receipts.

**Offline validation:** `python Mallory/ops/resource-identity-audit-v1/verify_offline.py` passed: the patch applied in a temporary tree and `python -m unittest Mallory.core.test_core Mallory.core.test_audit` passed (42 tests, 2 skipped). Java test code is staged but no JVM or campaign was run. Live `Mallory/core`, live instrumentation source, checklist, and completed evidence were not edited.
