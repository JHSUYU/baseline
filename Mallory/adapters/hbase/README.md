# HBase MiniCluster adapter

This adapter runs unchanged HBase 2.6.6 cluster JUnit methods in a fresh Java 8 JVM. It adds node and handoff probes at class load through an independent ASM transformer. The HBase source and distribution jars are not patched. Runtime artifact hashes and the direct JUnit command are pinned in [overlay-receipt.json](overlay-receipt.json).

## Runtime links

| HBase operation | Recorded relation |
| --- | --- |
| `HBaseTestingUtility.startMiniCluster` | Registers the returned master and region-server objects as `masterN` and `rsN`. |
| `JVMClusterUtil.MasterThread/RegionServerThread` construction and `HMaster/HRegionServer.run` | Registers each server from MiniCluster's explicit constructor index before its thread starts, then restores that actor for startup checks reached before `startMiniCluster` returns. |
| `HBaseTestingUtility.getConnection/getAdmin` | Registers the returned connection or admin object as `client`. Selected methods on `ConnectionImplementation` or `HBaseAdmin` enter that registered client scope. |
| `Call` creation and `IPCUtil.buildRequestHeader` | Assigns a unique request token and places it in HBase's request-header attributes. |
| `RpcServer.call` | Reads the transported token and enters the registered server scope. The call exit records the paired response token. |
| `RpcConnection.readResponse` and `AbstractRpcClient.callBlockingMethod` | Links an actually parsed response to the blocking caller without changing that caller's current occurrence. |
| `MasterProcedureEnv`, `AbstractProcedureScheduler.push/poll`, and `ProcedureExecutor.executeProcedure` | The versioned v4 adapter binds the scheduler to the explicit master and links each successful enqueue/dequeue attempt with a unique token. A procedure rescheduled several times therefore has separate causal handoffs. `MasterProcedureScheduler.clear` invalidates abandoned tokens. Fresh HBASE-17/18 MiniCluster runs observed a one-to-one submit/claim pair for every procedure attempt. |
| Selected master procedure method with `MasterProcedureEnv` as its first argument | Resolves the registered master from `env.getMasterServices()` when a check runs in the caller before procedure submission. |
| `ZKProcedureMemberRpcs.start` and `ZKProcedureCoordinator` construction | Registers explicit ZooKeeper procedure member and coordinator names as logical actors. Selected controller methods enter that actor scope, including MiniZKCluster tests without a MiniHBaseCluster. |
| `ResultBoundedCompletionService` and `QueueingFuture` | Links scanner submission, worker, and exact returned future to the waiting target region. |

The adapter never guesses a node from a thread name. An event before an explicit registration remains `unknown`. Unmatched tokens remain graph gaps; the controller does not invent a temporal edge.

## Case contract

Each case uses an existing cluster JUnit test, an exact target branch and `ATHROW` site, and a small `sites.json` with explicit fault doors. A source-backed alternate test needs its own versioned inventory and healthy calibration before the dispatcher can admit fault trials. The controller pins the loaded target class hash and requires a named target region in the healthy trial. For HBASE-01, the selected doors are the client meta scanner invocation and the server `BlockingService.callBlockingMethod` invocation in `RpcServer.call`. The server door can run under a named master or region server. IOException injection happens before that invocation.

Build the adapter with `mvn -q test package` in this directory. Campaign checkpoints and trial evidence are written by `Mallory.core.campaign`, so a stopped controller resumes from the next unfinished trial with the same config digest. The current HBASE-01 v2 run uses the immutable [v2 full config](pilot/HBASE-01-v2-full.json), fixed core release `5820a32d`, and its separately pinned v3 adapter.

The lane2 direct Java command enables assertions with `-ea`, since some selected HBase checks are Java `assert` statements. Target ownership is checked per case: a passing JUnit test alone does not establish that its selected branch was reached on a named node. The adapter recognizes the generic agent's `regionEnter` probe and wraps only selected client methods, so the client binding is not tied to a particular HBase check.
