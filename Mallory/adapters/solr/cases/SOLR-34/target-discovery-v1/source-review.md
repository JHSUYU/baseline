The selected check is in `CoordinatorHttpSolrCall.getCore` at lines 138–149 of the pinned Solr 8.11.4 source. The caller first reads the original collection and its config from ZooKeeper. When the synthetic collection is absent, it synchronously calls `createColl`; the `finally` block reads the synthetic collection from `ZkStateReader` again. The check at line 138 only executes if this second read still returns null. Line 139 distinguishes a failed create, which rethrows `createException` at line 140, from a create that returned without an exception but whose collection is still absent, which constructs the selected new `SolrException` at line 143. A rethrown create exception is **not** an exact SOLR-34 hit.
