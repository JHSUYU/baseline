# SOLR-39 watcher-state healthy admission

This is one **healthy-only** run of the unchanged Solr 8.11.4 `TimeRoutedAliasUpdateProcessorTest#test`. It starts four Jetty nodes, creates a time-routed alias, and sends commits and a delete through that alias. The earlier SOLR-39 calibration failed during ConfigSet creation, before alias setup; this package retains the independently observed fixture flags that let the same JUnit selector pass for SOLR-10. That SOLR-10 result does not prove the SOLR-39 target was reached.

The selected check is `RoutedAliasUpdateProcessor.lookupShardLeadersOfCollections` at line 246. It reads the `AliasesManager.aliases` cache through `ZkStateReader.getAliases`; a missing alias list throws at line 247. The target method has no I/O before its null guard. `AliasesManager.process` is a more direct fault candidate than a collection-property read: the ZooKeeper watch callback reads `/aliases.json` at line 2312 and calls `setIfNewer` at line 2314. It catches `ConnectionLossException` at lines 2317–2319, so a failed read can leave the cached alias unchanged while a later commit or delete still reaches the target. This is a source-backed hypothesis, not an observed causal path or a bug finding.

The case-local site catalog instruments the typed `SolrZkClient.getData` call in that callback. The agent includes `ZkStateReader$AliasesManager` explicitly, since including the outer class alone does not match its nested class. The pinned v38 adapter scopes watch callbacks to registered Solr server identities. `state.fields=true` records sampled write/read versions for the exact `AliasesManager#aliases` field; `SolrDispatchFilter` is included to scope the later HTTP update request. A sampled version can establish an observed write/read link, but it does not record the ZooKeeper payload or prove that a failed callback caused a missing alias. The healthy trace must distinguish these facts.

`python3 run_healthy.py --preflight-only` verifies source lines, compiled target and watcher bytecode, selected JUnit, adapter, agent, site catalog, and release without starting a JVM. A real run needs a dispatch GO receipt bound to this runner, config, node2, and fresh output directory. No GO receipt or JVM run is part of this stage. Full fault testing remains on hold until the healthy run passes one JUnit, observes the exact nonthrowing target on a named server, and records the watcher door and a defensible watcher-to-cache-to-guard path. If the watcher callback is not exercised, report that gap; do not infer it from source or event timestamps alone.
