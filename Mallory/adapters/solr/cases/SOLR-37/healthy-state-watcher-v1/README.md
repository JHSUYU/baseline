# SOLR-37 watcher-state healthy-only variant

This is a **separate, unlaunched** one-trial package for the unchanged `ShardSplitTest#test` JUnit and exact `DistributedZkUpdateProcessor.doDefensiveChecks@994` branch checks. It does not replace `original102-healthy-v1` or the archived v29a/v29p evidence. `admission-request.json` has `go=false`; this package cannot run without a matching dispatch healthy GO receipt. There is no fault or full-campaign admission.

The catalog selects only the source line 1641 `ZkStateReader.fetchCollectionState` call to `SolrZkClient.getData(String,Watcher,Stat,boolean)`, with `KeeperException.ConnectionLossException`. It also instruments `StateWatcher.refreshAndWatch(EventType)` as a region. The pinned v46 adapter and v46 direct-JUnit wrapper scope the real watcher method to the registered reader's physical server and log its collection, reader ID and cached collection version before/after. Its `solr31:` region label and SOLR-31-specific `@1641:door:watcher` fault hook remain in that immutable adapter, but the latter requires the unrelated `forceleader_lower_terms_collection` and is **not** selected here. This variant uses the generic catalog `@1641:door:1` event and must reject any event outside an actual watcher occurrence. Static preflight checks the source line, catch, compiled SolrJ classes, adapter SHA, exact catalog and frozen runtime inputs.

Local no-JVM preflight: `python3 static_preflight.py`; it verifies the pinned baseline source, JUnit, classes, adapter, catalog and case files, and explicitly leaves the node2 runtime checkout unverified. Dispatch must also run `python3 run_campaign.py --mode healthy --preflight-only` on node2 after staging the pinned worktree. Runtime admission, if dispatch later grants it, is `run_node2.sh healthy` with a matching `admission-healthy-node2.json`; the shell requires node2, exclusive case and shared Solr source locks, 7,650,410,496 free disk bytes and 8,388,608 KiB MemAvailable. The output path is separate under `data/mallory/solr37_state_watcher_healthy_v1_node2/SOLR-37/healthy`.

## Healthy observation gate

Require JUnit 1/0/0 and the exact nonthrowing `@994` target on an attested named physical server. A qualifying door must be `DOOR_OBSERVED` at `ZkStateReader#fetchCollectionState@1641:door:1` with the typed `getData` call, inside the same `StateWatcher.refreshAndWatch` occurrence, with a named server/epoch, registered reader ID and the test collection's `/collections/<collection>/state.json` path. The watcher read must precede a cache update/reconstruction on that reader; the later target must use that same reader and collection with measured `mySlice`/parent range operands. Order alone or a shared logical node is insufficient. A watcher callback and an update request on different threads constitute a state timeline, not an observed graph edge unless a real edge is recorded.

The existing v46 diagnostics log collection version and reader identity at the watcher, but do **not** record the SOLR-37 target's reader ID or range operands. Therefore this package is an observation probe; a positive `@1641` door and `@994` target alone do not close the handoff. Before any fault pilot, add separately pinned target-operand telemetry or another source-backed way to prove the same reader/cache version/ranges, then obtain a fresh healthy trace and a separate target-retention gate. The source audit is in `../source-gap-v1/README.md`.
