# SOLR-09 node0 successor package

This is an isolated **offline-staged** continuation of `runtime-role-v1` on node0. It uses the existing Solr 8.11.4 `DeleteReplicaTest#deleteReplicaAndVerifyDirectoryCleanup` cluster JUnit, the original `DeleteReplicaCmd.deleteCore` selected check, and the typed `OverseerCollectionMessageHandler.waitForCoreNodeGone` timeout door. The earlier JUnit reached the named check and same-occurrence door, but the new role-aware agent has no fresh healthy result yet. The first run must therefore validate its own healthy seed before scheduling any fault trial. A complete, naturally terminal campaign is the completion condition; graph path quality is reported as evidence.

The node0 checkout, distribution, pinned case-local agent/core, adapter JAR, site file, runner, and hashes are fixed by `config-full-node0.json` and `sha-manifest.json`. The node2 package under `runtime-role-v1` is unchanged. `run_campaign.py --preflight-only` validates these inputs without starting a JVM. The launcher requires a separate dispatch `admission-full-node0.json` with `go: true` bound to the exact config, runner, launcher, collector, package manifest, output, and already terminal SOLR-31 result. That GO file is intentionally absent from this package.

On admission, `run_full_node0.sh` takes both the node0 lane lock and the shared Solr source lock, checks a 6.5 GiB node0 disk reserve and 8 GiB available RAM, then runs at most 80 fault trials / 3600 seconds / 3 faults per trial. Output is fresh at `data/mallory/full_solr09_runtime_role_v1_node0/SOLR-09`. The runtime role selector resolves one physical node/epoch/occurrence per trial; a role mismatch is an invalid fault, not a matched injection.

`collect_offhost.py --watch` is the separate terminal collector. It waits for the launcher session to exit and a terminal result, verifies the full raw tree per member, then copies it to node2 with a 5 GiB floor on both hosts. `remote_finalize.py` verifies every member and atomically publishes the remote raw tree. The node0 raw tree stays intact; the compact collector receipt is written outside it. Node0 report promotion requires a later independent terminal audit and is not performed by this package.

The dispatcher should launch `run_full_node0.sh` in tmux session `mallory-solr09-node0-full` and `collect_offhost.py --watch` in a separate durable session. The collector's node2 receiver must retain the SHA in the package manifest. Recheck node0 disk immediately before admission: the launcher requires at least 6.5 GiB free, even though the collector's reserve is 5 GiB plus 64 MiB.

No Solr JVM was started while preparing this package. Run the offline tests with `python3 -m unittest -q Mallory/adapters/solr/cases/SOLR-09/node0-successor-v1/test_collector.py`.
