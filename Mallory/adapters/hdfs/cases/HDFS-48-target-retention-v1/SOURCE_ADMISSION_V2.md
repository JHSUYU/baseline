# HDFS-48 independent source admission

Review scope: Apache Hadoop 3.4.3 commit `9d50c6884666e794e45102260a4017bb31802e1b`, `TestRenameWithSnapshots#testRenameUndo_1`, and the selected `INodeDirectory.replaceChild` checks `@356:branch:2`, `@358:branch:3` with `Preconditions.checkState` call throw `@356:callthrow:11`. The original v14 fault-free JUnit passed 1/0/0, reached the nonthrowing check on `hdfs-cluster-1/nn0`, and passed its offline causal audit. The old NameNode `Server$RpcCall.run@1246` IOException pilot had ten effective faults and zero postfault targets. Those results establish the original healthy mapping and rule out that tested server ingress fault strategy; they do not validate a new client door.

## Exact source path

The JUnit creates a three-DataNode `MiniDFSCluster` in `setUp` (`TestRenameWithSnapshots.java:104-112`). In `testRenameUndo_1` (`1339-1362`) it builds two directories and files, takes a snapshot, installs a spy with a direct `root.replaceChild` call, then calls `hdfs.rename(foo, newfoo)` and expects `false`. The direct call is in the JUnit client actor and cannot count as the named NameNode target. The rename RPC enters `FSDirRenameOp`; its snapshot path calls `srcParent.replaceChild4ReferenceWithName` (`FSDirRenameOp.java:674-679`), which calls `replaceChild` (`INodeDirectory.java:381-399`). The selected guard is an in-memory child/reference identity check. The relevant edit-log sync follows rename processing, so it is not a pretarget file door.

The current, unmodified test has no caught pretarget IOException that source proves will preserve this NameNode target. `Server$RpcCall.run` invokes the handler inside a `try` (`Server.java:1243-1254`); its injected IOException is converted to an RPC error before the rename handler. The client sees a remote IOException, and `RetryUtils.WrapperRetryPolicy` retries remote exceptions only for its designated class (`RetryUtils.java:109-120`). The default `dfs.client.retry.policy.enabled` is `false` (`HdfsClientConfigKeys.java:354-361`). The archived ten-trial result matches that source path.

## Conditional client-door admission

The already staged patches in this directory form a source-backed *candidate*, with no built or runtime admission. `hadoop-test-retry.patch` enables `dfs.client.retry.policy.enabled=true` and `dfs.client.retry.policy.spec=20,1` before the cluster creates its `FileSystem`; the latter means one retry with a nominal 20 ms randomized sleep (`RetryPolicies.MultipleLinearRandomRetry`). The MiniDFSCluster client uses a non-HA `ClientProtocol` retry proxy (`NameNodeProxiesClient.java:125-139, 339-390`).

`hdfs-adapter-client-door.patch` puts `HdfsHooks.rpcBeforeSend` at entry to `Client.Connection.sendRpcRequest`, before serialization and `rpcRequestQueue.offer` (`Client.java:1159-1190`) and before the existing `rpcSend` hook. `RpcProtobufRequest.toString` gives `org.apache.hadoop.hdfs.protocol.ClientProtocol.rename` from the annotated protocol and protobuf request header (`ProtobufRpcEngine2.java:649-681`). The proposed method-specific site is `hdfs:client-send-rpc-request:rename`, typed `java.io.IOException`. A single injected local IOException here can escape `Client.call`, be wrapped as a `ServiceException` by the protobuf invocation, return to `IOException` through `ShadedProtobufHelper.ipc`, and be consumed by the enabled `RetryProxy` policy. Because the request is not queued, the retry can execute the rename once on the NameNode and reach the selected check. This is a source argument for target retention, not an observed postfault path.

`Client.getConnection` adds its `Call` to the connection map before `sendRpcRequest` (`Client.java:1620-1649`). The proposed pre-send exception skips a response for that call. The runtime trial must check pending-call cleanup, no spurious reply/correlation, and no shutdown delay. This is a concrete residual risk even though the rename itself has not been sent.

## Runtime identity and decision gate

Build the patches only after dispatch grants an isolated HDFS and adapter lane. Pin the patched adapter JAR and patched JUnit class before any healthy run. The JUnit transformer must scope the test thread as `hdfs-client`; the server target must remain the concrete `hdfs-cluster-1/nn0` actor. Require a fault-free Surefire 1/0/0 result, the exact nonthrowing named target, a catalogued `hdfs:client-send-rpc-request:rename` door, and a root-free event-time path from that client door through a successful matched RPC to the NameNode target. A direct JUnit-thread `root.replaceChild` event is ineligible.

Only after that healthy gate may a bounded single-fault pilot test one effective local IOException at the rename pre-send door. Require the exception to be caught by the configured retry, a later send for the same rename, the named exact target after the fault, and clean call-map/shutdown behavior. An event-time path cannot be inferred from method name or chronology alone. No patched JVM, fault trial, or full campaign was run for this review. The current disposition is **conditional source admission for an isolated healthy build**; target retention and runtime identity remain unverified.
