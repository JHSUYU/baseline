## Source and event contract

The existing `TestEncryptedTransfer#testLongLivedClient[0]` MiniDFSCluster workload selects the nontrusted parameter. The exact target is `BlockTokenSecretManager.retrievePassword(BlockTokenIdentifier)` at `allKeys.get(keyId)` / the subsequent null guard (`BlockTokenSecretManager.java:501–515`). A selected `InvalidToken` there is the sole oracle. The test's passing JUnit and healthy nonthrowing target are required before faults.

- `BPServiceActor.sendHeartBeat` is scoped by its actual `dn` receiver before the heartbeat attempt and the typed `sendHeartbeat` door at line 563. `BPOfferService.getBlockPoolId()` is package-private; the case hook now resolves declared zero-argument methods through the class hierarchy. The door may be selected only if its runtime node is named.
- `DatanodeProtocolClientSideTranslatorPB` has no `dn` field. Its completed reply RECV uses the `BPServiceActor.run` receiver already stored in `ACTOR_DATANODE` on that JVM thread. The response object is still matched by the exact Hadoop IPC correlation token. No thread-name or time-window pairing is used.
- The command queue's concrete Runnable is submitted before `BlockingQueue.put`, then claimed before `Runnable.run`. The claim opens a balanced region around that call. The region remains active while `BPOfferService.processCommandFromActive` switches to the exact decoded reply token and calls `BlockPoolTokenSecretManager.addKeys`; it closes on normal return and exception.
- The worker `BlockTokenSecretManager.addKeys` is synchronized. Its successful return hook records the actual stored `BlockKey` object for each exported integer key ID, an opaque manager identity, and a monotonically increasing per-key version. `retrievePassword` holds the same manager monitor while its `allKeys.get` returns; a hook immediately after that call records the returned value identity and version before the exact target check. No key bytes or raw token bytes enter the trace. A case-local auditor adds an observed read-from edge only for the same named DN/epoch, manager identity, key ID, value identity, version and state token, with no intervening write/remove/gap. A missing or different value rejects the edge. This is an explicit source-backed map relation; generic sampled `STATE_WRITE/READ` edges remain candidates in the frozen core.
- A `createPassword` method can be called twice on identical token identifier bytes in one RPC. The auditor retains both mint event IDs but groups them only if node, epoch, thread, request, block pool, key ID, digest and expiry all agree. The JUnit parser accepts only the exact indexed method and the strict per-trial Surefire classname suffix.

The healthy-only run is not a full campaign. The frozen core offline audit and the case-local `audit_timeline.py` must both be reported. A case-local strict witness must include `NN command → completed response SEND → named DN RECV → task SUBMIT/CLAIM → addKeys/key-state WRITE → exact key-state READ → target check`, with unique IPC and task tokens and valid event order. If either handoff or map identity is missing, the run remains calibration evidence and no fault is admitted. A full campaign remains separately gated by a postfault exact target path and the selected exception oracle.
