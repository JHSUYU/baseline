# HDFS-48 isolated rename pre-send healthy admission

This v4 package tests whether the exact HDFS-48 `INodeDirectory.replaceChild` check at source line 356 can be reached from a method-specific client request door. It is an isolated candidate, not a completed check or bug claim. The v3 pre-copy failure and its evidence remain untouched; v3 relied on `git rev-parse` in a node2 source copy whose `.git` directory is not a valid repository.

The original `TestRenameWithSnapshots#testRenameUndo_1` directly calls `replaceChild` in its test-thread setup and subsequently calls `hdfs.rename`. Only a target check on `hdfs-cluster-1/nn0` counts. The patched test enables one local `IOException` retry before constructing its MiniDFSCluster. The frozen HDFS adapter inspects `Client.Call.rpcRequest` at the beginning of `Client.Connection.sendRpcRequest`, accepts only the exact `org.apache.hadoop.hdfs.protocol.ClientProtocol.rename` request, and calls `Probe.beforeDoor` before the existing `rpcSend` event. It does not modify the shared adapter or Hadoop source.

`stage.py` pinned the shared adapter and original Hadoop test sources and built the isolated adapter on node0. A separate, temporary node0 copy of Hadoop compiled the patched JUnit class; that temporary copy was removed after preserving the class and SHA receipts. The compile did not run JUnit or start a cluster. `build-receipt.json` records the source and JAR identities. The original target class hash matched after the isolated compile. `source_identity.py` verifies the established 15,586-path Hadoop full-source digest plus selected target, test, and client source/class hashes without relying on local Git metadata.

Before any node2 run, dispatch must copy this package to node2 and grant `MALLORY_DISPATCH_ADMITTED=1`. `preflight.py --static` is read-only and works on node2 before any source copy or JVM. `run_healthy.sh` takes the node2 HDFS lane lock, performs that static check, prepares a separate Hadoop tree, verifies all pinned bytes, then runs **one fault-free JUnit trial**. The package does not launch a fault campaign. The strict healthy audit is `audit_healthy.py`: it requires JUnit 1/0/0; a nonthrowing exact target on nn0; a named `hdfs-client` rename pre-send door; an exact, uniquely matched `hadoop-ipc` request SEND/nn0 RECV correlation; and an observed event-time graph path through that request edge to the target. The direct setup check cannot satisfy this path.

The new door records the method by the pinned adapter filter, while the request correlation is produced by the existing `rpcSend` hook immediately after the door. A later bounded fault trial is appropriate only if the healthy path passes. Its result must separately establish a matched local `IOException`, a retry, target retention, and clean pending-call/shutdown behavior. No node2 v4 JUnit or fault trial has yet run.
