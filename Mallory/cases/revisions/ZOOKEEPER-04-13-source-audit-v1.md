# ZooKeeper source-only target and workload audit, revision 1

Date: 2026-10-09. Scope: original ZooKeeper sites `ZOOKEEPER-04` through
`ZOOKEEPER-13` in `data/crashfuzz/checklist102.json`. Source examined in a
clean Apache ZooKeeper `release-3.8.7` checkout at commit
`9085db92dd679e1e90a63bfe6ae6345ab6cbc4ae` (here called `ZKROOT`).
This is a source-based plan. No JVM workload, healthy trace, or fault trial
was run for this revision. Site locations below are the checklist's selected
lines; they need guard-level runtime identity checks before a campaign.

## Runtime selection rule

For these checks, a healthy selector should observe the **decision point**
in the named node and logical request or handshake, not merely wait for the
exception construction. The selected exception is the faulted-run oracle.
Record `check_reached`, `guard_outcome`, and `target_throw` separately.
Where the original test expects the exception, that exception is expected
behavior and must not be counted as a bug candidate.

`ZOOKEEPER-01` to `ZOOKEEPER-03` already have named cluster tests in the
checklist and are outside this revision's detailed scope. The direct session
owner path uses a client request/session ID, `PrepRequestProcessor` or
`ZooKeeperServer`, and the concrete tracker; do not merge two sessions or
two tracker instances because their check source line is the same.

| **04** `ZooKeeperServer.processConnectRequest:1441` | `ConnectionMetricsTest#testRevalidateCount` starts three peers, connects to follower 1, switches the client list to follower 2, shuts down follower 1, and reconnects. Select the **same client session's** connect request on follower 2 after the switch. | **05** `Follower.followLeader:103` | `QuorumRestartTest#testRollingRestart` starts three peers and restarts each in turn. | **06** `Leader.waitForEpochAck:1475` | Same rolling restart test. | **11** `QuorumPeer.loadDataBase:1175` | `CurrentEpochWriteFailureTest#testReadCurrentEpochFromAcceptedEpochTmpFile` starts three servers twice, then while stopped writes an old `currentEpoch` file and a matching current `currentEpoch.tmp` on the first server.
